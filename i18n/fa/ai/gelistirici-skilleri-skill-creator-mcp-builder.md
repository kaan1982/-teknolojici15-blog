برای کسی که نرم‌افزار می‌نویسد اسکیل‌ها از دو جهت جالب‌اند. اول، اسکیل‌های «سازنده» هستند که به نوشتن اسکیل‌های خودت سریع‌تر و قابل‌اندازه‌گیری کمک می‌کنند. دوم، بسته‌هایی هستند که به عامل انضباط مهندسی (تست، برنامه‌ریزی، رفع خطا) می‌دهند. در این مطلب هر دو را فقط با نمونه‌هایی که وجودشان را راستی‌آزمایی کرده‌ایم بررسی می‌کنیم.

## skill-creator: اسکیلی که اسکیل می‌نویسد

skill-creator در مخزن رسمی anthropics/skills از Anthropic برای ساخت اسکیل‌های تازه، ویرایش و بهبود اسکیل‌های موجود و اندازه‌گیری کارایی‌شان طراحی شده است. طبق توضیحش اجرای ارزیابی (eval)، مقایسه نتایج با تحلیل واریانس و بهینه‌سازی توضیح اسکیل برای فعال‌شدن بهتر را هم برعهده می‌گیرد.

گردش کار بسیار انسانی توصیف شده: تصمیم بگیر چه می‌خواهی، پیش‌نویس بنویس، چند پیام آزمایشی آماده کن، Claude دارای اسکیل را با این پیام‌ها اجرا کن، نتایج را با هم ارزیابی کن، دوباره بنویس، تکرار کن. در پوشه اسکریپت‌های جداگانه‌ای هست که ارزیابی اجرا می‌کنند، گزارش مقایسه تولید می‌کنند و توضیح را بهبود می‌دهند، و هم یک «eval-viewer» برای بررسی بصری نتایج.

راهنمای بهینه‌سازی توضیح در agentskills.io هم این اسکیل را مثال می‌زند. طبق راهنما، skill-creator این چرخه را از اول تا آخر خودکار می‌کند: مجموعه آزمون را تقسیم می‌کند، نرخ فعال‌شدن را موازی می‌سنجد، با Claude بهبودهای توضیح پیشنهاد می‌دهد و گزارش زنده HTML تولید می‌کند.

> **می‌دانستی؟** در آزمون فعال‌سازی پیشنهادی agentskills.io حدود 20 پیام نمونه به کار می‌رود و هرکدام 3 بار اجرا می‌شود. یعنی آزمودن یک توضیح تنها یعنی 60 اجرا. برای جلوگیری از برازش بیش‌ازحد (overfitting) حدود 60 درصد پیام‌ها برای بهبود و 40 درصد فقط برای اعتبارسنجی کنار گذاشته می‌شود. راهنما می‌گوید اغلب پنج دور کافی است.

## mcp-builder و claude-api: برای سازندگان یکپارچه‌سازی

- **mcp-builder (رسمی):** راهنمایی برای توسعه سرورهای MCP که به مدل‌های زبانی بزرگ اجازه می‌دهد از طریق ابزارهای خوب‌طراحی‌شده با سرویس‌های بیرونی صحبت کنند. با Python (FastMCP) یا Node/TypeScript (MCP SDK) کار می‌کند. اسکیل فرایند را به چهار مرحله تقسیم می‌کند: پژوهش و برنامه‌ریزی، پیاده‌سازی، بازبینی و تست، ساخت ارزیابی. در پوشه مستندات مرجع به تفکیک زبان و اسکریپت‌های ارزیابی هست.
- **claude-api (رسمی):** اسکیل مرجع برای Claude API و SDKهای Anthropic. موضوعاتی مثل شناسه مدل‌ها، پارامترها، جریان (streaming)، استفاده از ابزار، کش کردن را دربر می‌گیرد و برای زبان‌های برنامه‌نویسی بسیاری پوشه‌های جداگانه دارد. طبق مستندات Claude این اسکیل متن‌باز همراه Claude Code می‌آید.
- **webapp-testing (رسمی):** مجموعه ابزار برای تست برنامه‌های وب محلی با Playwright. کمک عملی‌ای که در مطلب طراحی هم برای توسعه‌دهندگان رابط جلویی ذکر کردیم.

## از جامعه: انضباط مهندسی با Superpowers

بیرون از مخزن رسمی، یکی از پرگفت‌وگوترین بسته‌ها میان توسعه‌دهندگان مخزن obra/superpowers از Jesse Vincent با مجوز MIT است. خودش را «روش‌شناسی کامل توسعه نرم‌افزار» برای عامل‌های کدنویسی معرفی می‌کند. تا اکتبر 2026 اسکیل‌های زیر (گزیده) در مخزن هست:

| اسکیل | چه زمانی فعال می‌شود؟ |
|---|---|
| brainstorming | پیش از شروع یک قابلیت تازه یا کار خلاقانه |
| writing-plans | هنگام نوشتن برنامه برای کاری چندمرحله‌ای، پیش از دست زدن به کد |
| test-driven-development | هنگام پیاده‌سازی: اول تست ناموفق، بعد کمترین کد |
| systematic-debugging | هنگام مواجهه با خطا یا تست ناموفق، پیش از پیشنهاد اصلاح |
| verification-before-completion | برای اجرای فرمان‌های راستی‌آزمایی پیش از گفتن «تمام شد» |

README مخزن علاوه بر Claude Code برای عامل‌های بسیاری مثل Codex، Cursor، Gemini CLI و GitHub Copilot CLI دستور نصب می‌دهد و می‌گوید در سمت Claude Code در بازار افزونه رسمی Anthropic هست. این هم پیامد عملی استاندارد باز بودن Agent Skills است: یک اسکیل می‌تواند در ابزارهای مختلف کار کند.

## در پلتفرم‌های دیگر هم همین ایده

مستندات ChatGPT و Codex از OpenAI هم اسکیل‌ها را مبتنی بر «استاندارد باز agent skills» توصیف می‌کنند. تا اکتبر 2026 در مستندات دو یاریگر داخلی برجسته است: skill-creator که از کاری که توصیف می‌کنی اسکیل می‌سازد (در Codex با $skill-creator فراخوانی می‌شود) و skill-installer که اسکیل آماده را از مخزن openai/skills یا مخزن‌های دیگر نصب می‌کند. Codex اسکیل‌های محلی را در سطح پروژه و کاربر از پوشه‌های .agents/skills می‌خواند.

برای یک توسعه‌دهنده ارزشمندترین عادت شاید این باشد: هر توضیح طولانی تکراری، فهرست بازبینی کد یا مراحل استقرار را به اسکیل تبدیل کنی و در مخزن پروژه بگذاری. در Claude Code اسکیل‌هایی که در پوشه .claude/skills گذاشته می‌شوند همراه مخزن به تیم هم می‌رسند. اما فراموش نکن اسکریپت‌های هر اسکیل جامعه‌ای را که نصب می‌کنی بخوانی، چون این اسکیل‌ها می‌توانند روی رایانه‌ات با اختیارات تو کد اجرا کنند.

در فرایند توسعه تو کدام مرحله بیشتر از همه باعث می‌شود بگویی «کاش یک اسکیل بود»: تست، بازبینی کد یا استقرار؟
