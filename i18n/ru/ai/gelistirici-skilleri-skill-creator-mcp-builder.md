Для тех, кто разрабатывает программы, skills интересны с двух сторон. Во-первых, есть «производящие» skills, помогающие писать собственные skills быстрее и измеримо. Во-вторых, есть пакеты, прививающие агенту инженерную дисциплину (тесты, планирование, отладка). В этой статье мы рассматриваем и то и другое, только на примерах, существование которых мы подтвердили.

## skill-creator: skill, который пишет skills

skill-creator из официального репозитория Anthropic anthropics/skills предназначен для создания новых skills, редактирования и улучшения существующих и измерения их производительности. Согласно его описанию, он берёт на себя и запуск оценок (eval), сравнение результатов с помощью дисперсионного анализа и оптимизацию описания skill так, чтобы он лучше срабатывал.

Рабочий процесс описан весьма по-человечески: реши, чего хочешь, напиши черновик, подготовь несколько тестовых сообщений, запусти Claude со skill на этих сообщениях, вместе оцени результаты, перепиши, повтори. В папке есть отдельные скрипты, запускающие оценку, создающие отчёт сравнения и улучшающие описание, а также «eval-viewer» для визуального просмотра результатов.

Руководство agentskills.io по оптимизации описаний тоже приводит этот skill как пример. По руководству, skill-creator автоматизирует этот цикл от начала до конца: разбивает тестовый набор, параллельно измеряет долю срабатываний, предлагает вместе с Claude улучшения описания и создаёт живой HTML-отчёт.

> **Знал ли ты?** В тесте срабатывания, который предлагает agentskills.io, используется около 20 примеров сообщений, и каждый запускается 3 раза. То есть проверка одного описания это 60 запусков. Чтобы избежать переобучения (overfitting), около 60 процентов сообщений отводится на улучшение, а 40 процентов только на проверку. Руководство говорит, что чаще всего хватает пяти раундов.

## mcp-builder и claude-api: для тех, кто создаёт интеграции

- **mcp-builder (официальный):** руководство по разработке MCP-серверов, позволяющих большим языковым моделям общаться с внешними сервисами через хорошо спроектированные инструменты. Работает с Python (FastMCP) или Node/TypeScript (MCP SDK). Skill разделяет процесс на четыре этапа: исследование и планирование, реализация, обзор и тестирование, создание оценок. В папке есть справочные документы по языкам и скрипты оценки.
- **claude-api (официальный):** справочный skill для Claude API и SDK Anthropic. Охватывает такие темы, как идентификаторы моделей, параметры, потоковая передача (streaming), использование инструментов, кэширование, и содержит отдельные папки для многих языков программирования. Согласно документации Claude, этот skill с открытым исходным кодом поставляется вместе с Claude Code.
- **webapp-testing (официальный):** набор инструментов для тестирования локальных веб-приложений с помощью Playwright. Практичный помощник, о котором мы упоминали и в статье о дизайне, для тех, кто разрабатывает фронтенд.

## От сообщества: Superpowers и инженерная дисциплина

Помимо официального репозитория, одним из самых обсуждаемых среди разработчиков пакетов является репозиторий obra/superpowers Джесси Винсента с лицензией MIT. Он называет себя «полной методологией разработки программного обеспечения» для агентов-программистов. По состоянию на октябрь 2026 года в репозитории есть следующие skills (подборка):

| Skill | Когда включается? |
|---|---|
| brainstorming | Перед началом новой функции или творческой работы |
| writing-plans | При составлении плана для многошаговой работы, прежде чем трогать код |
| test-driven-development | Во время реализации: сначала падающий тест, затем минимум кода |
| systematic-debugging | При столкновении с ошибкой или упавшим тестом, прежде чем предлагать исправление |
| verification-before-completion | Чтобы выполнить проверочные команды, прежде чем сказать «готово» |

README репозитория даёт инструкции по установке для многих агентов, таких как Codex, Cursor, Gemini CLI и GitHub Copilot CLI, помимо Claude Code, и отмечает, что для Claude Code он размещён в официальном маркетплейсе плагинов Anthropic. Это практическое следствие того, что Agent Skills открытый стандарт: один и тот же skill может работать в разных инструментах.

## Та же идея на других платформах

Документация OpenAI для ChatGPT и Codex тоже описывает skills как построенные на «открытом стандарте agent skills». По состоянию на октябрь 2026 года в документации выделяются два встроенных помощника: skill-creator, создающий skill из описанной тобой работы (в Codex вызывается через $skill-creator), и skill-installer, устанавливающий готовые skills из репозитория openai/skills или других репозиториев. Codex читает локальные skills из папок .agents/skills на уровне проекта и пользователя.

Самой ценной привычкой для разработчика может быть вот что: каждое длинное объяснение, которое ты повторяешь, свой контрольный список код-ревью или шаги развёртывания превращать в skill и класть в репозиторий проекта. В Claude Code skills, лежащие в папке .claude/skills, вместе с репозиторием попадают и к команде. Но не забывай читать скрипты каждого устанавливаемого community skill, потому что эти skills могут выполнять код на твоём компьютере с твоими правами.

Какой шаг в твоём процессе разработки чаще всего заставляет сказать «вот бы это был skill»: тестирование, код-ревью или развёртывание?
