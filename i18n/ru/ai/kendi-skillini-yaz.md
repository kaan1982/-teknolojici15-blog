Чтобы написать skill, программистом быть не нужно. В простейшем виде достаточно папки с одним текстовым файлом внутри. Но разница между хорошо работающим skill и skill, который никогда не срабатывает, чаще всего скрыта в одной фразе: описании. В этой статье мы с нуля пишем небольшой, но настоящий skill.

## Шаг 1: Создай папку и SKILL.md

Согласно спецификации Agent Skills, skill это папка, содержащая как минимум файл SKILL.md. В самом начале файла находится YAML-заголовок (frontmatter), и два поля обязательны:

- **name:** не более 64 символов. Только строчные буквы, цифры и дефис. Не может начинаться или заканчиваться дефисом, не может содержать два дефиса подряд и должно совпадать с именем папки. Документация Claude также отмечает, что слова «anthropic» и «claude» в имени использовать нельзя.
- **description:** не может быть пустым, не более 1024 символов. Должно описывать, что skill делает и когда его использовать.

Есть и необязательные поля (license, compatibility, metadata и экспериментальное allowed-tools), но для большинства skills они не нужны.

## Шаг 2: Тщательно напиши описание

Почему описание так важно? Потому что агент при запуске читает у каждого skill только имя и описание. По формулировке agentskills.io, «вся тяжесть» срабатывания лежит на описании. Если описание не говорит, когда работа пригодится, агент к этому skill не потянется.

Рекомендации источников можно резюмировать так:

- Пиши и **что он делает**, и **когда его использовать**.
- Документация Claude советует писать описание **в третьем лице**, так как оно добавляется в системный промпт («Обрабатывает файлы Excel», а не «Я могу тебе помочь»).
- agentskills.io советует прямо перечислять и случаи, когда пользователь не называет эту область по имени.
- Будь краток: несколько предложений, максимум короткий абзац. Claude Code обрезает описание в списке на 1536 символах, поэтому самый важный случай использования должен стоять в начале.

## Шаг 3: Держи тело коротким, а скрипт умным

В качестве примера представим skill в соответствии с правилом письма этого блога: в тексте не должно оставаться длинного тире (em dash) и среднего тире (en dash). Пусть структура папки будет такой:

```
tire-denetimi/
├── SKILL.md
└── scripts/
    └── tire_bul.py
```

А файл SKILL.md вот такой:

```markdown
---
name: tire-denetimi
description: Находит использование длинного тире (U+2014) и среднего тире (U+2013) в статьях блога и предлагает исправления. Применяется, когда пользователь готовит Markdown-статью к публикации, говорит «проверь тире», «соответствует ли правилам письма» или, не называя этого, хочет финальную проверку перед публикацией.
---

# Проверка тире

1. Выполни команду `python scripts/tire_bul.py <файл.md>`.
2. Для каждой строки в выводе предложи заменить тире точкой, запятой, двоеточием или скобками.
3. Не меняй смысл. Строки, в которых не уверен, уточни у пользователя.
4. В конце сообщи одним предложением, сколько строк исправлено.
```

Документация Claude рассматривает окно контекста как «общий ресурс» и советует добавлять только ту информацию, которой модель ещё не знает. Тело должно оставаться короче 500 строк. Длинные справочные тексты нужно выносить в отдельные файлы, а ссылаться на них из SKILL.md на одном уровне.

Правило для скриптов тоже ясно: «реши, а не перекладывай». То есть скрипт должен сам обрабатывать ошибочные ситуации, а не писаться по логике «пусть упадёт, Claude что-нибудь придумает». Когда скрипт выполняется, в контекст попадает не сам код, а только его вывод. Это делает скрипт надёжнее инструкции для повторяющихся и не терпящих ошибок задач.

> **Знал ли ты?** В Claude Code прежние «пользовательские слэш-команды» слились со skills. Файл .claude/commands/deploy.md и файл .claude/skills/deploy/SKILL.md создают одну и ту же команду /deploy. Если не хочешь, чтобы skill срабатывал автоматически, добавь во frontmatter disable-model-invocation: true, и его можно будет вызывать только вручную.

## Шаг 4: Протестируй, потом ещё раз протестируй

Руководство Claude по лучшим практикам советует перед написанием длинного документа подготовить сценарии оценки, а в контрольном списке перед публикацией значатся минимум три оценки и отдельное тестирование на моделях Haiku, Sonnet и Opus. Довод простой: инструкция, идеально работающая на Opus, может требовать больше подробностей для Haiku.

Для проверки срабатывания рекомендация agentskills.io конкретна: подготовь около 20 примеров сообщений пользователя. Из них 8-10 должны запускать skill, а 8-10 не должны. Самые ценные отрицательные примеры это «чуть не попали», то есть сообщения, использующие те же слова, но просящие другую работу. Поскольку поведение модели не всегда одинаково, советуют прогонять каждое сообщение несколько раз (для начала 3) и смотреть долю срабатываний.

| Плохое описание | Хорошее описание |
|---|---|
| «Помогает с PDF.» | Говорит, что делает и когда использовать |
| Только технические подробности | Описывает намерение пользователя |
| Охватывает всё | Указывает и чего не делает |

Установка тоже проста: в Claude Code достаточно положить папку в ~/.claude/skills/ (личная) или в папку .claude/skills/ проекта. Claude Code отслеживает эти папки и замечает изменения в том же сеансе без перезапуска. В claude.ai skill можно загрузить в настройках в виде zip.
