ИИ-ассистенты немного знают обо всём, но не знают шаблона отчёта твоей компании, цветов твоего бренда или тонкостей правильной обработки определённого типа файлов. А что если вместо того, чтобы подробно объяснять это в каждом чате, ты мог бы один раз упаковать всё и сказать агенту: «используй, когда понадобится»? Именно такова идея «skill» (навыка).

## Коротко: папка и SKILL.md

По определению Anthropic, Agent Skills это модульные пакеты, расширяющие возможности Claude. Каждый skill объединяет инструкции, метаданные и необязательные ресурсы (скрипты, шаблоны), а Claude использует их сам, когда они уместны. В инженерном блоге Anthropic об этом сказано ещё проще: skills это «организованные папки с инструкциями, скриптами и ресурсами», которые агент загружает в нужный момент, чтобы лучше справляться с определёнными задачами.

Технически skill это папка, в которой есть как минимум файл SKILL.md. В начале этого файла в формате YAML есть два обязательных поля: name (имя) и description (описание). Ниже идут инструкции, написанные обычным Markdown. В папку при желании можно добавить подпапки, такие как scripts/ (исполняемый код), references/ (дополнительные документы) и assets/ (шаблоны, изображения, данные).

Anthropic сравнивает эту структуру с руководством по адаптации для нового сотрудника. Ты кладёшь руководство на стол, и сотрудник открывает его, когда ему нужно.

## Секрет: не всё загружается сразу

Skills отличает от обычного длинного промпта дизайн, называемый «поэтапной загрузкой» (progressive disclosure). Согласно документации Claude, содержимое загружается в три уровня:

| Уровень | Когда загружается? |
|---|---|
| 1. Метаданные (имя + описание) | Всегда, при запуске (около 100 токенов на skill) |
| 2. Тело SKILL.md | При срабатывании skill (рекомендуется менее 5000 токенов) |
| 3. Дополнительные файлы и скрипты | Только при необходимости; в контекст попадает лишь вывод скриптов |

Благодаря этому можно загрузить в агента десятки skills, но они не заполнят окно контекста. До срабатывания «на столе» лежат только имя и описание каждого skill. В примере из документации skill для PDF хранит инструкции по заполнению форм в отдельном файле forms.md, и Claude читает этот файл только тогда, когда действительно заполняет форму.

> **Знал ли ты?** Anthropic объявила Agent Skills 16 октября 2025 года, а 18 декабря 2025 года опубликовала формат как открытый стандарт на agentskills.io. Поэтому по состоянию на октябрь 2026 года ту же структуру SKILL.md можно увидеть и в документации других инструментов, таких как GitHub Copilot и OpenAI Codex. Документация Copilot для проверки skills прямо отсылает к спецификации agentskills.io.

## Промпт, MCP, плагин: в чём разница?

Эти понятия часто путают, потому что все они о том, как «сделать агента лучше». Различие, которое проводит Справочный центр Claude, можно резюмировать так:

- **Промпт или пользовательские инструкции:** общие указания, действующие в каждом чате или во всех чатах. Skill же специфичен для задачи и включается только тогда, когда уместен.
- **Проекты:** постоянная справочная информация, всегда загруженная в чатах внутри проекта. Skill же процедура, которая открывается при необходимости.
- **Коннекторы MCP (Model Context Protocol):** подключают Claude к внешним сервисам и источникам данных. То есть обеспечивают «доступ». Skill же «знание метода», объясняющее, как пользоваться этим доступом. Справочный центр отмечает, что их часто используют вместе.
- **Плагины:** на стороне Claude Code и Cowork плагин это пакет для совместной поставки нескольких частей (skills, коннекторов, команд, субагентов). Документация OpenAI проводит похожее различие: skill это формат написания, плагин способ распространения.

Коротко: MCP даёт агенту руку, skill учит эту руку навыку, а плагин доставляет всё это в одной коробке.

## Где это работает?

По состоянию на октябрь 2026 года, согласно документации Claude, skills доступны в приложениях Claude (claude.ai), в Claude Code и в Claude API вместе с инструментом выполнения кода. Справочный центр отмечает, что skills предлагаются в тарифах Free, Pro, Max, Team и Enterprise и требуют включённой функции выполнения кода.

Важная деталь: пользовательские skills не синхронизируются между поверхностями. Skill, загруженный в claude.ai, принадлежит только твоей учётной записи. Skill, загруженный в API, доступен всему рабочему пространству. В Claude Code он хранится в личной (~/.claude/skills/) или проектной папке (.claude/skills/).

Есть и аспект безопасности. Поскольку skills могут выполнять код, документация советует относиться к ним «как к установке программного обеспечения» и использовать только из надёжных источников. Об этом мы отдельно говорим в последней статье серии.
