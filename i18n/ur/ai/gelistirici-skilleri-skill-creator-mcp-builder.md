سافٹ ویئر بنانے والے کے لیے skills دو لحاظ سے دلچسپ ہیں۔ پہلا، ایسی "تخلیق کار" skills ہیں جو اپنی skills کو زیادہ تیزی سے اور ناپے جا سکنے والے انداز میں لکھنے میں مدد دیتی ہیں۔ دوسرا، ایسے پیکیج ہیں جو ایجنٹ کو انجینئرنگ کا نظم (ٹیسٹ، منصوبہ، ڈیبگنگ) سکھاتے ہیں۔ اس تحریر میں ہم دونوں کو ان مثالوں کے ساتھ لیتے ہیں جن کے وجود کی ہم نے تصدیق کی ہے۔

## skill-creator: skill لکھنے والی skill

Anthropic کی سرکاری anthropics/skills ریپوزٹری میں موجود skill-creator نئی skills بنانے، موجودہ skills کو ایڈٹ اور بہتر کرنے اور ان کی کارکردگی ناپنے کے لیے ڈیزائن کی گئی ہے۔ اس کی وضاحت کے مطابق وہ جانچ (eval) چلانے، نتائج کو تغیر کے تجزیے سے موازنہ کرنے اور skill کی وضاحت کو بہتر متحرک ہونے کے لیے بہتر بنانے کا کام بھی سنبھالتی ہے۔

ورک فلو کافی انسانی انداز میں بیان کیا گیا ہے: طے کریں کہ کیا چاہیے، مسودہ لکھیں، چند ٹیسٹ پیغامات تیار کریں، skill والے Claude کو ان پیغامات کے ساتھ چلائیں، نتائج مل کر جانچیں، دوبارہ لکھیں، دہرائیں۔ فولڈر میں جانچ چلانے والے، موازنہ رپورٹ بنانے والے اور وضاحت بہتر کرنے والے الگ اسکرپٹس ہیں، اور نتائج کو بصری طور پر دیکھنے کے لیے ایک "eval-viewer" بھی موجود ہے۔

agentskills.io کی وضاحت کی اصلاح والی گائیڈ بھی اس skill کو مثال کے طور پر پیش کرتی ہے۔ گائیڈ کے مطابق skill-creator یہ چکر شروع سے آخر تک خودکار بنا دیتی ہے: ٹیسٹ سیٹ تقسیم کرتی ہے، متحرک ہونے کی شرحیں متوازی ناپتی ہے، Claude کے ساتھ وضاحت کی بہتریاں تجویز کرتی ہے اور ایک زندہ HTML رپورٹ بناتی ہے۔

> **کیا آپ جانتے ہیں؟** agentskills.io کی تجویز کردہ متحرک ہونے کی جانچ میں تقریباً 20 نمونہ پیغامات استعمال ہوتے ہیں اور ہر ایک کو 3 بار چلایا جاتا ہے۔ یعنی ایک وضاحت آزمانے کا مطلب 60 اجرا ہے۔ حد سے زیادہ موافقت (overfitting) روکنے کے لیے پیغامات کا تقریباً 60 فیصد بہتری کے لیے اور 40 فیصد صرف تصدیق کے لیے الگ رکھا جاتا ہے۔ گائیڈ کہتی ہے کہ اکثر پانچ دور کافی ہوتے ہیں۔

## mcp-builder اور claude-api: انضمام بنانے والوں کے لیے

- **mcp-builder (سرکاری):** بڑے لسانی ماڈلز کو اچھی ڈیزائن کردہ ٹولز کے ذریعے بیرونی سروسز سے بات کرنے کے قابل بنانے والے MCP سرور بنانے کی گائیڈ۔ Python (FastMCP) یا Node/TypeScript (MCP SDK) کے ساتھ کام کرتی ہے۔ Skill عمل کو چار مرحلوں میں بانٹتی ہے: تحقیق اور منصوبہ بندی، نفاذ، جائزہ اور ٹیسٹ، جانچ کی تیاری۔ فولڈر میں زبان کے مطابق حوالہ جاتی دستاویزات اور جانچ کے اسکرپٹس ہیں۔
- **claude-api (سرکاری):** Claude API اور Anthropic SDKs کے لیے حوالہ جاتی skill۔ ماڈل شناخت کنندگان، پیرامیٹرز، اسٹریمنگ، ٹول استعمال، کیشنگ جیسے موضوعات کا احاطہ کرتی ہے اور کئی پروگرامنگ زبانوں کے لیے الگ فولڈر رکھتی ہے۔ Claude دستاویزات کے مطابق یہ اوپن سورس skill Claude Code کے ساتھ آتی ہے۔
- **webapp-testing (سرکاری):** مقامی ویب ایپلیکیشنز کو Playwright سے ٹیسٹ کرنے کا ٹول سیٹ۔ ڈیزائن والی تحریر میں بھی ہم نے جس کا ذکر کیا، فرنٹ اینڈ بنانے والوں کے لیے ایک عملی معاون۔

## کمیونٹی سے: Superpowers کے ساتھ انجینئرنگ کا نظم

سرکاری ریپوزٹری سے باہر ڈویلپرز میں سب سے زیادہ زیرِ بحث پیکیجز میں سے ایک Jesse Vincent کی MIT لائسنس والی obra/superpowers ریپوزٹری ہے۔ وہ اپنے آپ کو کوڈنگ ایجنٹس کے لیے "سافٹ ویئر ڈویلپمنٹ کا مکمل طریقۂ کار" بتاتی ہے۔ اکتوبر 2026 تک ریپوزٹری میں یہ skills موجود ہیں (انتخاب):

| Skill | کب متحرک ہوتی ہے؟ |
|---|---|
| brainstorming | کوئی نیا فیچر یا تخلیقی کام شروع کرنے سے پہلے |
| writing-plans | کئی مراحل والے کام کے لیے کوڈ کو چھوئے بغیر منصوبہ لکھتے وقت |
| test-driven-development | نفاذ کے دوران: پہلے ناکام ٹیسٹ، پھر کم سے کم کوڈ |
| systematic-debugging | کوئی خرابی یا ناکام ٹیسٹ ملنے پر، حل تجویز کرنے سے پہلے |
| verification-before-completion | "ہو گیا" کہنے سے پہلے تصدیقی کمانڈز چلانے کے لیے |

ریپوزٹری کا README Claude Code کے علاوہ Codex، Cursor، Gemini CLI اور GitHub Copilot CLI جیسے کئی ایجنٹس کے لیے انسٹالیشن ہدایات دیتا ہے اور بتاتا ہے کہ Claude Code کی طرف وہ Anthropic کی سرکاری پلگ ان مارکیٹ میں موجود ہے۔ یہ Agent Skills کے کھلے معیار ہونے کا عملی نتیجہ ہے: ایک ہی skill مختلف ٹولز میں چل سکتی ہے۔

## دوسرے پلیٹ فارمز پر بھی یہی خیال

OpenAI کی ChatGPT اور Codex دستاویزات بھی skills کو "کھلے agent skills معیار" پر مبنی بتاتی ہیں۔ اکتوبر 2026 تک دستاویزات میں دو بلٹ ان معاون نمایاں ہیں: آپ کے بیان کردہ کام سے skill بنانے والی skill-creator (Codex میں $skill-creator سے بلائی جاتی ہے) اور openai/skills ریپوزٹری یا دوسری ریپوزٹریز سے تیار skills انسٹال کرنے والی skill-installer۔ Codex مقامی skills پروجیکٹ اور صارف کی سطح پر .agents/skills فولڈروں سے پڑھتا ہے۔

ایک ڈویلپر کے لیے سب سے قیمتی عادت شاید یہ ہو: ہر لمبی وضاحت جو آپ دہراتے ہیں، آپ کی کوڈ ریویو چیک لسٹ یا تعیناتی کے مراحل کو skill میں بدل کر پروجیکٹ کی ریپوزٹری میں رکھنا۔ Claude Code میں .claude/skills فولڈر میں رکھی گئی skills ریپوزٹری کے ساتھ ٹیم تک بھی پہنچتی ہیں۔ لیکن جو بھی کمیونٹی skill آپ انسٹال کریں اس کے اسکرپٹس پڑھنا نہ بھولیں، کیونکہ یہ skills آپ کے کمپیوٹر پر آپ کے اختیارات کے ساتھ کوڈ چلا سکتی ہیں۔

آپ کے ڈویلپمنٹ کے عمل میں کون سا مرحلہ سب سے زیادہ "کاش اس کے لیے skill ہوتی" کہلواتا ہے: ٹیسٹ، کوڈ ریویو یا تعیناتی؟
