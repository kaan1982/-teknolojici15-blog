Για κάποιον που αναπτύσσει λογισμικό, τα skills είναι ενδιαφέροντα από δύο πλευρές. Πρώτον, υπάρχουν skills «παραγωγής» που σε βοηθούν να γράφεις τα δικά σου skills πιο γρήγορα και με μετρήσιμο τρόπο. Δεύτερον, υπάρχουν πακέτα που δίνουν στον πράκτορα μηχανική πειθαρχία (δοκιμές, σχεδιασμό, εντοπισμό σφαλμάτων). Σε αυτό το άρθρο εξετάζουμε και τα δύο, μόνο με παραδείγματα των οποίων την ύπαρξη έχουμε επαληθεύσει.

## skill-creator: το skill που γράφει skills

Το skill-creator του επίσημου αποθετηρίου anthropics/skills της Anthropic έχει σχεδιαστεί για να δημιουργεί νέα skills, να επεξεργάζεται και να βελτιώνει τα υπάρχοντα και να μετρά την απόδοσή τους. Σύμφωνα με την περιγραφή του, αναλαμβάνει επίσης την εκτέλεση αξιολογήσεων (evals), τη σύγκριση των αποτελεσμάτων με ανάλυση διακύμανσης και τη βελτιστοποίηση της περιγραφής ενός skill ώστε να ενεργοποιείται καλύτερα.

Η ροή εργασίας περιγράφεται με αρκετά ανθρώπινο τρόπο: αποφάσισε τι θέλεις, γράψε ένα προσχέδιο, ετοίμασε μερικά δοκιμαστικά μηνύματα, τρέξε το Claude με το skill σε αυτά τα μηνύματα, αξιολογήστε μαζί τα αποτελέσματα, ξαναγράψε, επανέλαβε. Στον φάκελο υπάρχουν ξεχωριστά σενάρια που τρέχουν αξιολογήσεις, παράγουν αναφορά σύγκρισης και βελτιώνουν την περιγραφή, καθώς και ένα «eval-viewer» για να εξετάζεις τα αποτελέσματα οπτικά.

Και ο οδηγός βελτιστοποίησης περιγραφών του agentskills.io αναφέρει αυτό το skill ως παράδειγμα. Σύμφωνα με τον οδηγό, το skill-creator αυτοματοποιεί αυτόν τον κύκλο από την αρχή μέχρι το τέλος: χωρίζει το σύνολο δοκιμών, μετρά παράλληλα τα ποσοστά ενεργοποίησης, προτείνει βελτιώσεις της περιγραφής με τη βοήθεια του Claude και παράγει μια ζωντανή αναφορά HTML.

> **Το ήξερες;** Στη δοκιμή ενεργοποίησης που προτείνει το agentskills.io χρησιμοποιούνται περίπου 20 δείγματα μηνυμάτων και το καθένα τρέχει 3 φορές. Δηλαδή η δοκιμή μιας μόνο περιγραφής σημαίνει 60 εκτελέσεις. Για να αποφευχθεί η υπερπροσαρμογή (overfitting), περίπου το 60% των μηνυμάτων αφιερώνεται στη βελτίωση και το 40% μόνο στην επαλήθευση. Ο οδηγός λέει ότι τις περισσότερες φορές αρκούν πέντε γύροι.

## mcp-builder και claude-api: για όσους χτίζουν ενσωματώσεις

- **mcp-builder (επίσημο):** Οδηγός για την ανάπτυξη διακομιστών MCP που επιτρέπουν στα μεγάλα γλωσσικά μοντέλα να συνομιλούν με εξωτερικές υπηρεσίες μέσω καλά σχεδιασμένων εργαλείων. Λειτουργεί με Python (FastMCP) ή Node/TypeScript (MCP SDK). Το skill χωρίζει τη διαδικασία σε τέσσερις φάσεις: έρευνα και σχεδιασμός, υλοποίηση, επισκόπηση και δοκιμή, δημιουργία αξιολογήσεων. Στον φάκελο υπάρχουν έγγραφα αναφοράς ανά γλώσσα και σενάρια αξιολόγησης.
- **claude-api (επίσημο):** Skill αναφοράς για το Claude API και τα SDK της Anthropic. Καλύπτει θέματα όπως αναγνωριστικά μοντέλων, παραμέτρους, streaming, χρήση εργαλείων και caching, και περιέχει ξεχωριστούς φακέλους για πολλές γλώσσες προγραμματισμού. Σύμφωνα με την τεκμηρίωση του Claude, αυτό το skill ανοιχτού κώδικα συνοδεύει το Claude Code.
- **webapp-testing (επίσημο):** Εργαλειοθήκη για τη δοκιμή τοπικών web εφαρμογών με Playwright. Ένας πρακτικός βοηθός για όσους αναπτύσσουν front end, που αναφέραμε και στο άρθρο για τον σχεδιασμό.

## Από την κοινότητα: πειθαρχία μηχανικής με το Superpowers

Εκτός από το επίσημο αποθετήριο, ένα από τα πακέτα που συζητιούνται περισσότερο ανάμεσα στους προγραμματιστές είναι το αποθετήριο obra/superpowers του Jesse Vincent, με άδεια MIT. Περιγράφει τον εαυτό του ως «μια πλήρη μεθοδολογία ανάπτυξης λογισμικού» για πράκτορες προγραμματισμού. Από τον Οκτώβριο του 2026, το αποθετήριο περιέχει τα εξής skills (επιλογή):

| Skill | Πότε ενεργοποιείται; |
|---|---|
| brainstorming | Πριν ξεκινήσεις ένα νέο χαρακτηριστικό ή μια δημιουργική δουλειά |
| writing-plans | Όταν γράφεις σχέδιο για μια εργασία πολλών βημάτων, πριν αγγίξεις τον κώδικα |
| test-driven-development | Κατά την υλοποίηση: πρώτα ένα αποτυχημένο τεστ, μετά ο ελάχιστος κώδικας |
| systematic-debugging | Όταν συναντάς ένα σφάλμα ή ένα τεστ που αποτυγχάνει, πριν προτείνεις διόρθωση |
| verification-before-completion | Για να τρέχεις εντολές επαλήθευσης πριν πεις «τελείωσα» |

Το README του αποθετηρίου δίνει οδηγίες εγκατάστασης για πολλούς πράκτορες, εκτός από το Claude Code, όπως το Codex, το Cursor, το Gemini CLI και το GitHub Copilot CLI, και αναφέρει ότι για το Claude Code υπάρχει στην επίσημη αγορά πρόσθετων της Anthropic. Αυτό είναι το πρακτικό αποτέλεσμα του ότι τα Agent Skills είναι ανοιχτό πρότυπο: το ίδιο skill μπορεί να λειτουργεί σε διαφορετικά εργαλεία.

## Η ίδια ιδέα και σε άλλες πλατφόρμες

Και η τεκμηρίωση του ChatGPT και του Codex της OpenAI περιγράφει τα skills ως βασισμένα στο «ανοιχτό πρότυπο agent skills». Από τον Οκτώβριο του 2026 ξεχωρίζουν στην τεκμηρίωση δύο ενσωματωμένοι βοηθοί: το skill-creator, που δημιουργεί ένα skill από τη δουλειά που περιγράφεις (στο Codex καλείται με $skill-creator), και το skill-installer, που εγκαθιστά έτοιμα skills από το αποθετήριο openai/skills ή από άλλα αποθετήρια. Το Codex διαβάζει τα τοπικά skills από τους φακέλους .agents/skills σε επίπεδο έργου και χρήστη.

Για έναν προγραμματιστή η πιο πολύτιμη συνήθεια ίσως είναι αυτή: κάθε μακρά εξήγηση που επαναλαμβάνεις, η λίστα ελέγχου της επισκόπησης κώδικα ή τα βήματα της διανομής, να γίνονται ένα skill που μπαίνει στο αποθετήριο του έργου. Στο Claude Code, τα skills που μπαίνουν στον φάκελο .claude/skills φτάνουν στην ομάδα μαζί με το αποθετήριο. Μην ξεχνάς όμως να διαβάζεις τα σενάρια κάθε skill της κοινότητας που εγκαθιστάς, γιατί αυτά τα skills μπορούν να εκτελούν κώδικα στον υπολογιστή σου με τα δικά σου δικαιώματα.

Σε ποιο βήμα της δικής σου διαδικασίας ανάπτυξης λες πιο συχνά «μακάρι να υπήρχε ένα skill»: στις δοκιμές, στην επισκόπηση κώδικα ή στη διανομή;
