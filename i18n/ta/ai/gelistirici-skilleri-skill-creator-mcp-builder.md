மென்பொருள் உருவாக்கும் ஒருவருக்கு skill-கள் இரண்டு வகையில் சுவாரஸ்யமானவை. முதலாவது, உன் சொந்த skill-களை வேகமாகவும் அளவிடக்கூடிய முறையிலும் எழுத உதவும் "உருவாக்கி" skill-கள். இரண்டாவது, முகவருக்கு பொறியியல் ஒழுக்கத்தை (சோதனை, திட்டம், பிழைத்திருத்தம்) கொடுக்கும் தொகுப்புகள். இந்தக் கட்டுரையில் இரண்டையும், இருப்பதை உறுதிசெய்த எடுத்துக்காட்டுகளுடன் மட்டுமே பார்க்கிறோம்.

## skill-creator: skill எழுதும் skill

Anthropic-இன் அதிகாரப்பூர்வ anthropics/skills களஞ்சியத்தில் உள்ள skill-creator, புதிய skill-களை உருவாக்கவும், இருக்கும் skill-களைத் திருத்தி மேம்படுத்தவும், அவற்றின் செயல்திறனை அளக்கவும் வடிவமைக்கப்பட்டது. அதன் விளக்கத்தின்படி மதிப்பீடுகளை (eval) இயக்குதல், முடிவுகளை மாறுபாட்டுப் பகுப்பாய்வுடன் ஒப்பிடுதல், skill விளக்கத்தை சிறப்பாகத் தூண்டும் வகையில் மேம்படுத்துதல் ஆகிய வேலைகளையும் ஏற்கிறது.

பணிப்பாய்வு மிகவும் மனிதத்தன்மையுடன் விவரிக்கப்பட்டுள்ளது: என்ன வேண்டும் என்று முடிவு செய், வரைவு எழுது, சில சோதனைச் செய்திகளைத் தயார் செய், skill-உடன் கூடிய Claude-ஐ இந்தச் செய்திகளுடன் இயக்கு, முடிவுகளை இணைந்து மதிப்பிடு, மீண்டும் எழுது, மீண்டும் செய். கோப்புறையில் மதிப்பீடுகளை இயக்கும், ஒப்பீட்டு அறிக்கை உருவாக்கும், விளக்கத்தை மேம்படுத்தும் தனி ஸ்கிரிப்டுகளும், முடிவுகளைக் காட்சியாக ஆய்வு செய்ய ஒரு "eval-viewer"-உம் உள்ளன.

agentskills.io-வின் விளக்க மேம்படுத்தல் வழிகாட்டியும் இந்த skill-ஐ எடுத்துக்காட்டாகக் காட்டுகிறது. வழிகாட்டியின்படி skill-creator இந்தச் சுழற்சியை தொடக்கம் முதல் முடிவு வரை தானியக்கமாக்குகிறது: சோதனைத் தொகுப்பைப் பிரிக்கிறது, தூண்டல் விகிதங்களை இணையாக அளக்கிறது, Claude மூலம் விளக்க மேம்பாடுகளைப் பரிந்துரைக்கிறது, நேரடி HTML அறிக்கையை உருவாக்குகிறது.

> **உனக்குத் தெரியுமா?** agentskills.io பரிந்துரைக்கும் தூண்டல் சோதனையில் சுமார் 20 மாதிரிச் செய்திகள் பயன்படுத்தப்படுகின்றன, ஒவ்வொன்றும் 3 முறை இயக்கப்படுகிறது. அதாவது ஒரே ஒரு விளக்கத்தைச் சோதிப்பது 60 இயக்கங்கள். அதிகப்படியான பொருத்தத்தைத் (overfitting) தடுக்க, செய்திகளில் சுமார் 60 சதவீதம் மேம்படுத்தலுக்கும், 40 சதவீதம் சரிபார்ப்புக்கு மட்டும் ஒதுக்கப்படுகின்றன. பெரும்பாலும் ஐந்து சுற்றுகள் போதும் என்று வழிகாட்டி கூறுகிறது.

## mcp-builder மற்றும் claude-api: ஒருங்கிணைப்புகளை அமைப்பவர்களுக்கு

- **mcp-builder (அதிகாரப்பூர்வம்):** பெரிய மொழி மாதிரிகள் வெளிச் சேவைகளுடன் நன்கு வடிவமைக்கப்பட்ட கருவிகள் வழியாகப் பேச உதவும் MCP சேவையகங்களை உருவாக்குவதற்கான வழிகாட்டி. Python (FastMCP) அல்லது Node/TypeScript (MCP SDK) உடன் இயங்குகிறது. இந்த skill செயல்முறையை நான்கு கட்டங்களாகப் பிரிக்கிறது: ஆய்வும் திட்டமிடலும், செயலாக்கம், மதிப்பாய்வும் சோதனையும், மதிப்பீடுகளை உருவாக்குதல். கோப்புறையில் மொழிவாரியான குறிப்பு ஆவணங்களும் மதிப்பீட்டு ஸ்கிரிப்டுகளும் உள்ளன.
- **claude-api (அதிகாரப்பூர்வம்):** Claude API மற்றும் Anthropic SDK-களுக்கான குறிப்பு skill. மாதிரி அடையாளங்கள், அளவுருக்கள், ஸ்ட்ரீமிங், கருவிப் பயன்பாடு, தற்காலிகச் சேமிப்பு போன்றவற்றை உள்ளடக்குகிறது; பல நிரலாக்க மொழிகளுக்கு தனி கோப்புறைகளையும் கொண்டுள்ளது. Claude ஆவணங்களின்படி இந்தத் திறந்த மூல skill Claude Code-உடன் சேர்ந்தே வருகிறது.
- **webapp-testing (அதிகாரப்பூர்வம்):** உள்ளூர் வலைச் செயலிகளை Playwright மூலம் சோதிப்பதற்கான கருவித்தொகுப்பு. வடிவமைப்புக் கட்டுரையிலும் குறிப்பிட்டபடி, முன்பக்க உருவாக்குநர்களுக்கு நடைமுறையில் பயனுள்ள உதவியாளர்.

## சமூகத்திலிருந்து: Superpowers மூலம் பொறியியல் ஒழுக்கம்

அதிகாரப்பூர்வ களஞ்சியத்துக்கு வெளியே உருவாக்குநர்களிடையே அதிகம் பேசப்படும் தொகுப்புகளில் ஒன்று, Jesse Vincent-இன் MIT உரிமம் கொண்ட obra/superpowers களஞ்சியம். தன்னை குறியீட்டு முகவர்களுக்கான "முழுமையான மென்பொருள் உருவாக்க முறைமை" என்று விவரிக்கிறது. அக்டோபர் 2026 நிலவரப்படி களஞ்சியத்தில் இந்த skill-கள் உள்ளன (தேர்வு):

| Skill | எப்போது செயல்படும்? |
|---|---|
| brainstorming | புதிய அம்சம் அல்லது படைப்பு வேலையைத் தொடங்கும் முன் |
| writing-plans | பல படிகள் கொண்ட வேலைக்கு, குறியீட்டைத் தொடும் முன் திட்டம் எழுதும்போது |
| test-driven-development | செயலாக்கத்தின்போது: முதலில் தோல்வியடையும் சோதனை, பிறகு குறைந்தபட்சக் குறியீடு |
| systematic-debugging | ஒரு பிழை அல்லது தோல்வியடைந்த சோதனையைச் சந்திக்கும்போது, திருத்தத்தைப் பரிந்துரைக்கும் முன் |
| verification-before-completion | "முடிந்தது" என்று சொல்லும் முன் சரிபார்ப்புக் கட்டளைகளை இயக்க |

களஞ்சியத்தின் README, Claude Code தவிர Codex, Cursor, Gemini CLI, GitHub Copilot CLI போன்ற பல முகவர்களுக்கும் நிறுவல் அறிவுறுத்தல் தருகிறது; Claude Code பக்கம் Anthropic-இன் அதிகாரப்பூர்வ செருகுநிரல் சந்தையில் இடம்பெற்றிருப்பதாகவும் குறிப்பிடுகிறது. இது Agent Skills திறந்த தரநிலையாக இருப்பதன் நடைமுறை விளைவு: அதே skill வெவ்வேறு கருவிகளில் இயங்க முடியும்.

## பிற தளங்களிலும் அதே எண்ணம்

OpenAI-இன் ChatGPT மற்றும் Codex ஆவணங்களும் skill-களை "திறந்த agent skills தரநிலை" மீது கட்டப்பட்டவையாக விவரிக்கின்றன. அக்டோபர் 2026 நிலவரப்படி ஆவணங்களில் இரண்டு உள்ளமைந்த உதவியாளர்கள் முன்னிலையில் உள்ளன: நீ விவரிக்கும் வேலையிலிருந்து skill உருவாக்கும் skill-creator (Codex-இல் $skill-creator மூலம் அழைக்கப்படுகிறது), openai/skills களஞ்சியத்திலிருந்தோ பிற களஞ்சியங்களிலிருந்தோ தயார் skill-களை நிறுவும் skill-installer. Codex உள்ளூர் skill-களைத் திட்ட மற்றும் பயனர் மட்டத்தில் .agents/skills கோப்புறைகளிலிருந்து படிக்கிறது.

ஓர் உருவாக்குநருக்கு மிகவும் மதிப்புமிக்க பழக்கம் இதுவாக இருக்கலாம்: நீ திரும்பத் திரும்ப விளக்கும் ஒவ்வொரு நீண்ட விளக்கத்தையும், குறியீட்டு மதிப்பாய்வுப் பட்டியலையும், வெளியீட்டுப் படிகளையும் ஒரு skill-ஆக மாற்றி திட்டத்தின் களஞ்சியத்தில் வைப்பது. Claude Code-இல் .claude/skills கோப்புறையில் வைக்கப்படும் skill-கள் களஞ்சியத்துடன் சேர்ந்து குழுவுக்கும் செல்கின்றன. ஆனால் நீ நிறுவும் ஒவ்வொரு சமூக skill-இன் ஸ்கிரிப்டுகளையும் படிக்க மறக்காதே, ஏனெனில் இந்த skill-கள் உன் கணினியில் உன் அனுமதிகளுடன் குறியீட்டை இயக்க முடியும்.

உன் உருவாக்கச் செயல்முறையில் எந்தப் படி "ஒரு skill இருந்தால் நன்றாக இருக்குமே" என்று அதிகம் எண்ண வைக்கிறது: சோதனையா, குறியீட்டு மதிப்பாய்வா, வெளியீடா?
