Skill எழுத நீ நிரலாளராக இருக்க வேண்டியதில்லை. மிக எளிய வடிவில் ஒரு கோப்புறையும் அதற்குள் ஒரே ஒரு உரைக் கோப்பும் போதும். ஆனால் நன்கு இயங்கும் skill-க்கும் ஒருபோதும் தூண்டப்படாத skill-க்கும் இடையிலான வேறுபாடு, பெரும்பாலும் ஒரே ஒரு வாக்கியத்தில் ஒளிந்துள்ளது: விளக்கம். இந்தக் கட்டுரையில் புதிதாக, சிறிய ஆனால் உண்மையான skill-ஐ எழுதுகிறோம்.

## படி 1: கோப்புறையையும் SKILL.md-ஐயும் உருவாக்கு

Agent Skills விவரக்குறிப்பின்படி ஒரு skill என்பது குறைந்தது ஒரு SKILL.md கோப்பைக் கொண்ட கோப்புறை. கோப்பின் தொடக்கத்தில் YAML முன்தகவல் (frontmatter) இருக்கும்; இரண்டு புலங்கள் கட்டாயம்:

- **name:** அதிகபட்சம் 64 எழுத்துகள். சிறிய எழுத்துகள், இலக்கங்கள், இடைக்கோடு மட்டும். இடைக்கோட்டுடன் தொடங்கவோ முடியவோ கூடாது, தொடர்ச்சியாக இரண்டு இடைக்கோடுகள் இருக்கக்கூடாது, கோப்புறையின் பெயருடன் ஒன்றாக இருக்க வேண்டும். "anthropic", "claude" சொற்களைப் பெயரில் பயன்படுத்தக்கூடாது என்றும் Claude ஆவணங்கள் குறிப்பிடுகின்றன.
- **description:** காலியாக இருக்கக்கூடாது, அதிகபட்சம் 1,024 எழுத்துகள். Skill என்ன செய்கிறது, எப்போது பயன்படுத்தப்பட வேண்டும் என்பதை விளக்க வேண்டும்.

விருப்பப் புலங்களும் உள்ளன (license, compatibility, metadata, சோதனை நிலையிலுள்ள allowed-tools), ஆனால் பெரும்பாலான skill-களுக்கு அவை தேவையில்லை.

## படி 2: விளக்கத்தைக் கவனமாக எழுது

விளக்கம் ஏன் இவ்வளவு முக்கியம்? ஏனெனில் முகவர் தொடக்கத்தில் ஒவ்வொரு skill-இன் பெயரையும் விளக்கத்தையும் மட்டுமே படிக்கிறது. agentskills.io-வின் சொற்களில் தூண்டலின் "முழுச் சுமையும்" விளக்கத்தின் தோளில். விளக்கம் இந்த வேலை எப்போது பயன்படும் என்று சொல்லவில்லை என்றால், முகவர் அந்த skill-ஐ நாடாது.

ஆதாரங்களின் பரிந்துரைகளை இப்படிச் சுருக்கலாம்:

- **என்ன செய்கிறது** என்பதையும் **எப்போது பயன்படுத்த வேண்டும்** என்பதையும் எழுது.
- விளக்கம் அமைப்பு அறிவுறுத்தலில் சேர்க்கப்படுவதால் **மூன்றாம் நபரில்** எழுதும்படி Claude ஆவணங்கள் பரிந்துரைக்கின்றன ("Excel கோப்புகளைச் செயலாக்குகிறது", "உனக்கு உதவ முடியும்" அல்ல).
- பயனர் அந்தத் துறையை பெயரால் குறிப்பிடாத சூழ்நிலைகளையும் வெளிப்படையாகப் பட்டியலிடும்படி agentskills.io பரிந்துரைக்கிறது.
- சுருக்கமாக வை: சில வாக்கியங்கள், அதிகபட்சம் சிறிய ஒரு பத்தி. Claude Code பட்டியலில் விளக்கத்தை 1,536 எழுத்தில் வெட்டுகிறது; எனவே மிக முக்கியமான பயன்பாட்டுச் சூழல் தொடக்கத்தில் இருக்க வேண்டும்.

## படி 3: உடலைச் சுருக்கமாகவும் ஸ்கிரிப்டை புத்திசாலித்தனமாகவும் வை

எடுத்துக்காட்டாக இந்த வலைப்பதிவின் சொந்த எழுத்து விதிக்கு ஏற்ற ஒரு skill-ஐ நினைத்துப் பார்: உரையில் நீண்ட கோடு (em dash), நடுத்தர கோடு (en dash) இருக்கக்கூடாது. கோப்புறை அமைப்பு இப்படி இருக்கட்டும்:

```
tire-denetimi/
├── SKILL.md
└── scripts/
    └── tire_bul.py
```

SKILL.md கோப்பு இவ்வளவுதான்:

```markdown
---
name: tire-denetimi
description: துருக்கிய வலைப்பதிவுக் கட்டுரைகளில் நீண்ட கோடு (U+2014), நடுத்தர கோடு (U+2013) பயன்பாட்டைக் கண்டறிந்து திருத்தம் பரிந்துரைக்கிறது. பயனர் ஒரு Markdown கட்டுரையை வெளியீட்டுக்குத் தயாரிக்கும்போது, "கோடுகளைச் சரிபார்", "எழுத்து விதிகளுக்கு இணங்குகிறதா" என்று சொல்லும்போது, அல்லது பெயர் குறிப்பிடாவிட்டாலும் வெளியீட்டுக்கு முந்தைய இறுதிச் சரிபார்ப்பைக் கேட்கும்போது பயன்படுத்தப்படுகிறது.
---

# Tire denetimi

1. `python scripts/tire_bul.py <dosya.md>` கட்டளையை இயக்கு.
2. வெளியீட்டில் உள்ள ஒவ்வொரு வரிக்கும் கோட்டை புள்ளி, காற்புள்ளி, முக்காற்புள்ளி அல்லது அடைப்புக்குறியால் மாற்றப் பரிந்துரை.
3. பொருளை மாற்றாதே. உறுதியில்லாத வரிகளை பயனரிடம் கேள்.
4. இறுதியில் எத்தனை வரிகளைத் திருத்தினாய் என்பதை ஒரே வாக்கியத்தில் தெரிவி.
```

Claude ஆவணங்கள் சூழல் சாளரத்தை "பொதுச் சொத்தாக" பார்க்கின்றன; மாதிரி ஏற்கெனவே அறியாத தகவலை மட்டுமே சேர்க்கும்படி பரிந்துரைக்கின்றன. உடல் 500 வரிகளுக்குள் இருக்க வேண்டும். நீண்ட குறிப்பு உரைகள் தனிக் கோப்புகளுக்கு மாற்றப்பட்டு, SKILL.md-இலிருந்து ஒரே நிலையில் இணைப்பு தரப்பட வேண்டும்.

ஸ்கிரிப்டுகளுக்கான விதியும் தெளிவு: "தீர்த்துவை, பந்தை வீசாதே". அதாவது ஸ்கிரிப்ட் பிழை நிலைகளைத் தானே கையாள வேண்டும், "வெடிக்கட்டும், Claude ஏதாவது வழி கண்டுபிடிக்கும்" என்ற தர்க்கத்தில் எழுதப்படக்கூடாது. ஸ்கிரிப்ட் இயங்கும்போது சூழலுக்குள் குறியீடு அல்ல, அதன் வெளியீடு மட்டுமே நுழைகிறது. இது திரும்பத் திரும்ப நடக்கும், பிழை பொறுக்காத வேலைகளுக்கு ஸ்கிரிப்டை அறிவுறுத்தலை விட நம்பகமாக்குகிறது.

> **உனக்குத் தெரியுமா?** Claude Code-இல் பழைய "தனிப்பயன் சாய்வுக்கோடு கட்டளைகள்" skill-களுடன் இணைந்துவிட்டன. .claude/commands/deploy.md கோப்பும் .claude/skills/deploy/SKILL.md கோப்பும் ஒரே /deploy கட்டளையை உருவாக்குகின்றன. ஒரு skill தானாகத் தூண்டப்படுவதை நீ விரும்பவில்லை என்றால், frontmatter-இல் disable-model-invocation: true சேர்த்து அதைக் கையால் மட்டுமே அழைக்கலாம்.

## படி 4: சோதி, பிறகு மீண்டும் சோதி

Claude-இன் சிறந்த நடைமுறைகள் வழிகாட்டி, நீண்ட ஆவணம் எழுதுவதற்கு முன் மதிப்பீட்டுச் சூழ்நிலைகளைத் தயாரிக்கும்படி பரிந்துரைக்கிறது; வெளியீட்டுக்கு முந்தைய சரிபார்ப்புப் பட்டியலில் குறைந்தது மூன்று மதிப்பீடுகளும் Haiku, Sonnet, Opus மாதிரிகளில் தனித்தனிச் சோதனையும் உள்ளன. காரணம் எளிது: Opus-இல் குறைவின்றி இயங்கும் அறிவுறுத்தலுக்கு Haiku-வுக்கு அதிக விவரம் தேவைப்படலாம்.

தூண்டலைச் சோதிக்க agentskills.io-வின் பரிந்துரை உறுதியானது: சுமார் 20 மாதிரிப் பயனர் செய்திகளைத் தயாரி. அவற்றில் 8 முதல் 10 skill-ஐத் தூண்ட வேண்டும், 8 முதல் 10 தூண்டக்கூடாது. மிக மதிப்புமிக்க எதிர்மறை எடுத்துக்காட்டுகள் "நூலிழையில் தவறுபவை": அதே சொற்களைப் பகிரும் ஆனால் வேறு வேலையைக் கேட்கும் செய்திகள். மாதிரியின் நடத்தை ஒவ்வொரு முறையும் ஒரே மாதிரி இருக்காததால், ஒவ்வொரு செய்தியையும் பல முறை (தொடக்கத்துக்கு 3) இயக்கி தூண்டல் விகிதத்தைப் பார்க்கும்படி பரிந்துரைக்கப்படுகிறது.

| மோசமான விளக்கம் | நல்ல விளக்கம் |
|---|---|
| "PDF-களில் உதவுகிறது." | என்ன செய்கிறது, எப்போது பயன்படுத்த வேண்டும் என்று சொல்கிறது |
| தொழில்நுட்ப விவரம் மட்டும் | பயனரின் நோக்கத்தை விளக்குகிறது |
| எல்லாவற்றையும் உள்ளடக்குகிறது | எதைச் செய்யாது என்பதையும் குறிப்பிடுகிறது |

நிறுவலும் எளிது: Claude Code-இல் கோப்புறையை ~/.claude/skills/ கீழே (தனிப்பட்ட) அல்லது திட்டத்தின் .claude/skills/ கோப்புறையில் வைத்தால் போதும். Claude Code இந்தக் கோப்புறைகளைக் கண்காணித்து, மாற்றங்களை மறுதொடக்கம் இல்லாமல் அதே அமர்வில் கண்டறிகிறது. claude.ai-இல் skill-ஐ zip ஆக அமைப்புகளிலிருந்து பதிவேற்றலாம்.

உன் முதல் skill, உன் எந்தத் திரும்பத் திரும்ப நடக்கும் வேலையைத் தானியக்கமாக்கும்?
