עוזרי בינה מלאכותית יודעים קצת מכל דבר, אבל הם לא מכירים את תבנית הדוחות של החברה שלכם, את צבעי המותג שלכם או את הטריקים לעיבוד נכון של סוג קובץ מסוים. מה אם במקום להסביר זאת בהרחבה בכל שיחה, הייתם יכולים לארוז את זה פעם אחת ולומר לסוכן "השתמש בזה כשצריך"? זה בדיוק הרעיון של "skill" (מיומנות).

## בקצרה: תיקייה ו-SKILL.md

לפי ההגדרה של Anthropic, Agent Skills הם חבילות מודולריות שמרחיבות את היכולות של Claude. כל skill מחזיק יחד הוראות, מטא-נתונים ומשאבים אופציונליים (סקריפטים, תבניות), ו-Claude משתמש בהם מעצמו כשהם רלוונטיים. הבלוג ההנדסי של Anthropic אומר זאת בפשטות רבה יותר: skills הם "תיקיות מאורגנות של הוראות, סקריפטים ומשאבים" שהסוכן טוען ברגע הצורך כדי להיות טוב יותר במשימות מסוימות.

מבחינה טכנית skill הוא תיקייה שיש בה לפחות קובץ בשם SKILL.md. בראש הקובץ הזה, בפורמט YAML, יש שני שדות חובה: name (שם) ו-description (תיאור). מתחתיהם נמצאות הוראות שנכתבו ב-Markdown רגיל. לתיקייה אפשר להוסיף, אם רוצים, תיקיות משנה כמו scripts/ (קוד שניתן להפעלה), references/ (מסמכים נוספים) ו-assets/ (תבניות, תמונות, נתונים).

Anthropic משווה את המבנה הזה למדריך קליטה שמכינים לעובד חדש. אתם משאירים את המדריך על השולחן, והעובד פותח ומעיין בו כשהוא צריך.

## הסוד: הכול לא נטען בבת אחת

מה שמבדיל skills מפרומפט ארוך רגיל הוא העיצוב שנקרא "גילוי הדרגתי" (progressive disclosure). לפי התיעוד של Claude, התוכן נטען בשלוש שכבות:

| שכבה | מתי היא נטענת? |
|---|---|
| 1. מטא-נתונים (שם + תיאור) | תמיד, בהפעלה (כ-100 טוקנים לכל skill) |
| 2. גוף SKILL.md | כשה-skill מופעל (מומלץ מתחת ל-5,000 טוקנים) |
| 3. קבצים וסקריפטים נוספים | רק כשצריך; מהסקריפטים נכנס להקשר רק הפלט |

כך אפשר לטעון לסוכן עשרות skills בלי שכולם ימלאו את חלון ההקשר. עד שה-skill מופעל, רק השם והתיאור של כל אחד נמצאים "על השולחן". בדוגמה שבתיעוד, ה-skill של PDF שומר את ההוראות למילוי טפסים בקובץ נפרד בשם forms.md, ו-Claude קורא את הקובץ הזה רק כשהוא באמת ממלא טופס.

> **הידעת?** Anthropic הכריזה על Agent Skills ב-16 באוקטובר 2025 ופרסמה את הפורמט כתקן פתוח בכתובת agentskills.io ב-18 בדצמבר 2025. לכן נכון לאוקטובר 2026 אפשר לראות את אותו מבנה SKILL.md גם בתיעוד של כלים אחרים כמו GitHub Copilot ו-OpenAI Codex. התיעוד של Copilot מפנה ישירות למפרט agentskills.io לצורך בדיקת skills.

## פרומפט, MCP, תוסף: מה ההבדלים?

המושגים האלה מתבלבלים לעיתים קרובות, כי כולם נוגעים ל"שיפור הסוכן". ההבחנה של מרכז העזרה של Claude מסוכמת כך:

- **פרומפט או הוראות מותאמות:** הנחיות כלליות שחלות בכל שיחה או בכל השיחות. skill, לעומת זאת, ספציפי למשימה ונכנס לפעולה רק כשהוא רלוונטי.
- **פרויקטים:** ידע רקע קבוע שנטען תמיד בשיחות בתוך פרויקט. skill הוא נוהל שנפתח כשצריך.
- **מחברי MCP (Model Context Protocol):** מחברים את Claude לשירותים חיצוניים ולמקורות נתונים. כלומר מספקים "גישה". skill הוא "ידע שיטתי" שמסביר איך להשתמש בגישה הזו. מרכז העזרה אומר ששניהם משמשים לעיתים קרובות יחד.
- **תוספים (plugin):** בצד Claude Code ו-Cowork, תוסף הוא החבילה להפצת כמה חלקים (skills, מחברים, פקודות, תת-סוכנים) יחד. גם התיעוד של OpenAI עושה הבחנה דומה: skill הוא פורמט הכתיבה, ותוסף הוא צורת ההפצה.

בקיצור, MCP נותן לסוכן יד, skill מלמד את היד מיומנות, ותוסף מספק אותם בקופסה אחת.

## איפה זה עובד?

נכון לאוקטובר 2026, לפי התיעוד של Claude, אפשר להשתמש ב-skills באפליקציות Claude (claude.ai), ב-Claude Code וב-Claude API יחד עם כלי הרצת הקוד. מרכז העזרה מציין ש-skills מוצעים בתוכניות Free, Pro, Max, Team ו-Enterprise ודורשים שתכונת הרצת הקוד תהיה פעילה.

פרט חשוב: skills מותאמים אישית אינם מסונכרנים בין הממשקים. skill שהעליתם ל-claude.ai הוא פרטי לחשבון שלכם בלבד. skill שהועלה ל-API משותף עם כל סביבת העבודה. ב-Claude Code הוא נשמר באופן אישי (~/.claude/skills/) או בתיקיית הפרויקט (.claude/skills/).

יש גם ממד של אבטחה. מכיוון ש-skills יכולים להריץ קוד, התיעוד ממליץ להתייחס אליהם "כמו להתקנת תוכנה" ולהשתמש בהם רק ממקורות מהימנים. את זה אנחנו מסבירים בנפרד בכתבה האחרונה בסדרה.

בכתבות הבאות בפרק הזה נכתוב צעד אחר צעד skill משלכם ונבחן קטגוריה אחר קטגוריה את ה-skills שבאמת קיימים ושימושיים.

מהי המשימה שאתם מסבירים לבינה המלאכותית שוב ושוב בכל יום ואומרים "הלוואי שהייתי מלמד אותה את זה פעם אחת"?
