למי שמפתח תוכנה, skills מעניינים משתי בחינות. הראשונה: יש skills "מייצרים" שעוזרים לכתוב skills משלכם מהר יותר ובצורה מדידה. השנייה: יש חבילות שנותנות לסוכן משמעת הנדסית (בדיקות, תכנון, דיבוג). בכתבה הזו אנחנו עוסקים בשתיהן, רק בדוגמאות שאימתנו את קיומן.

## skill-creator: skill שכותב skills

skill-creator במאגר הרשמי של Anthropic, anthropics/skills, תוכנן ליצירת skills חדשים, לעריכה ושיפור של skills קיימים ולמדידת הביצועים שלהם. לפי התיאור שלו הוא גם לוקח על עצמו הרצת הערכות (eval), השוואת תוצאות בניתוח שונות ואופטימיזציה של תיאור ה-skill כך שיופעל טוב יותר.

זרימת העבודה מתוארת בצורה אנושית למדי: החליטו מה אתם רוצים, כתבו טיוטה, הכינו כמה הודעות בדיקה, הריצו את Claude עם ה-skill על ההודעות האלה, הערכו את התוצאות יחד, כתבו מחדש, חזרו. בתיקייה יש סקריפטים נפרדים שמריצים הערכות, מפיקים דוח השוואה ומשפרים את התיאור, וכן "eval-viewer" לבחינה חזותית של התוצאות.

גם המדריך לאופטימיזציית תיאורים של agentskills.io מציג את ה-skill הזה כדוגמה. לפי המדריך, skill-creator מבצע אוטומציה של הלולאה הזו מקצה לקצה: הוא מפצל את קבוצת הבדיקה, מודד שיעורי הפעלה במקביל, מציע שיפורי תיאור עם Claude ומפיק דוח HTML חי.

> **הידעת?** בבדיקת ההפעלה שמציע agentskills.io משתמשים בכ-20 הודעות לדוגמה, וכל אחת מורצת 3 פעמים. כלומר כדי לנסות תיאור אחד צריך 60 הרצות. כדי למנוע התאמת יתר (overfitting) כ-60 אחוז מההודעות מוקצים לשיפור, ו-40 אחוז רק לאימות. המדריך אומר שברוב המקרים חמישה סבבים מספיקים.

## mcp-builder ו-claude-api: למי שבונה אינטגרציות

- **mcp-builder (רשמי):** מדריך לפיתוח שרתי MCP שמאפשרים למודלי שפה גדולים לדבר עם שירותים חיצוניים דרך כלים מתוכננים היטב. פועל עם Python (FastMCP) או Node/TypeScript (MCP SDK). ה-skill מחלק את התהליך לארבעה שלבים: מחקר ותכנון, מימוש, סקירה ובדיקה, יצירת הערכות. בתיקייה יש מסמכי עיון לפי שפה וסקריפטים להערכה.
- **claude-api (רשמי):** skill עיון עבור Claude API וערכות ה-SDK של Anthropic. מכסה נושאים כמו מזהי מודלים, פרמטרים, זרימה (streaming), שימוש בכלים ומטמון, וכולל תיקיות נפרדות לשפות תכנות רבות. לפי תיעוד Claude, ה-skill בקוד פתוח הזה מגיע יחד עם Claude Code.
- **webapp-testing (רשמי):** ערכת כלים לבדיקת אפליקציות אינטרנט מקומיות עם Playwright. עוזר מעשי למפתחי ממשק קדמי שהזכרנו גם בכתבת העיצוב.

## מהקהילה: Superpowers ומשמעת הנדסית

מחוץ למאגר הרשמי, אחת החבילות המדוברות ביותר בקרב מפתחים היא המאגר obra/superpowers של ג'סי וינסנט ברישיון MIT. הוא מגדיר את עצמו כ"מתודולוגיית פיתוח תוכנה שלמה" לסוכני קידוד. נכון לאוקטובר 2026, במאגר ה-skills האלה (מבחר):

| Skill | מתי הוא נכנס לפעולה? |
|---|---|
| brainstorming | לפני תחילת תכונה חדשה או עבודה יצירתית |
| writing-plans | בכתיבת תוכנית לעבודה רב-שלבית לפני נגיעה בקוד |
| test-driven-development | במהלך המימוש: קודם בדיקה שנכשלת, ואז הכי פחות קוד |
| systematic-debugging | כשנתקלים בתקלה או בבדיקה שנכשלה, לפני שמציעים תיקון |
| verification-before-completion | להרצת פקודות אימות לפני שאומרים "סיימתי" |

ה-README של המאגר נותן הוראות התקנה לסוכנים רבים כמו Codex, Cursor, Gemini CLI ו-GitHub Copilot CLI, לצד Claude Code, ומציין שבצד Claude Code הוא נמצא בשוק התוספים הרשמי של Anthropic. זו התוצאה המעשית של היות Agent Skills תקן פתוח: אותו skill יכול לפעול בכלים שונים.

## אותו רעיון בפלטפורמות אחרות

גם התיעוד של OpenAI ל-ChatGPT ול-Codex מגדיר skills כמבוססים על "תקן agent skills הפתוח". נכון לאוקטובר 2026 בולטים בתיעוד שני עוזרים מובנים: skill-creator שיוצר skill מהעבודה שתיארתם (נקרא ב-Codex באמצעות $skill-creator) ו-skill-installer שמתקין skills מוכנים מהמאגר openai/skills או ממאגרים אחרים. Codex קורא skills מקומיים מתיקיות .agents/skills ברמת הפרויקט והמשתמש.

ההרגל השווה ביותר עבור מפתח הוא אולי זה: כל הסבר ארוך שאתם חוזרים עליו, רשימת הבדיקה לסקירת קוד או שלבי הפריסה, להפוך ל-skill ולהניח במאגר הפרויקט. ב-Claude Code, skills שמונחים בתיקיית .claude/skills הולכים עם המאגר גם לצוות. אבל אל תשכחו לקרוא את הסקריפטים של כל skill קהילתי שאתם מתקינים, כי ה-skills האלה יכולים להריץ קוד במחשב שלכם עם ההרשאות שלכם.

איזה שלב בתהליך הפיתוח שלכם גורם לכם הכי הרבה לומר "הלוואי שהיה skill": בדיקות, סקירת קוד או פריסה?
