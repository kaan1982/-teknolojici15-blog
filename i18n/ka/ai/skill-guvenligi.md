რაც skill-ებს ასე ძლიერს ხდის, იგივე ხდის მათ სარისკოსაც: skill მხოლოდ ტექსტს კი არა, გასაშვებ კოდსაც შეიძლება შეიცავდეს. როცა აგენტი skill-ს ტვირთავს, მასში არსებულ ინსტრუქციებს საკუთარი ინსტრუქციებივით მიჰყვება და მის სკრიპტებს გაუშვებს. ამიტომ Claude-ის დოკუმენტაციის რჩევა ერთ წინადადებაში ჯდება: skill-ის დაყენება პროგრამის დაყენებად მიიჩნიე.

## რას ამბობს ოფიციალური წყაროები?

Claude-ის დოკუმენტაციის უსაფრთხოების ნაწილი საკმაოდ პირდაპირია. ის გირჩევს, skill-ები გამოიყენო მხოლოდ სანდო წყაროებიდან, ანუ ისეთები, რომლებიც თავად დაწერე ან Anthropic-ისგან აიღე. თუ უცნობი წყაროდან skill-ის გამოყენება გიწევს, გთხოვს, „უკიდურესად ფრთხილად“ იყო და გამოყენებამდე თავიდან ბოლომდე შეამოწმო.

Anthropic-ის საინჟინრო სტატიაც იმავე ხაზზეა: ნაკლებად სანდო წყაროებიდან მიღებულ skill-ებში გირჩევს შეფუთული ფაილების, განსაკუთრებით კოდის დამოკიდებულებებისა და სკრიპტების, შემოწმებას, ასევე იმ ინსტრუქციების შემოწმებას, რომლებიც გარე ქსელებთან დაკავშირებას ითხოვს. დოკუმენტაცია ერთ რისკსაც განსაკუთრებით ხაზს უსვამს: skill-ები, რომლებიც გარე მისამართებიდან მონაცემებს იღებს, სახიფათოა, რადგან მიღებული შინაარსი ბოროტ ინსტრუქციებს შეიძლება შეიცავდეს.

## რა ხდება რეალობაში?

ეს გაფრთხილებები თეორიული არ არის. უსაფრთხოების კომპანია Snyk-მა 2026 წლის 5 თებერვალს გამოქვეყნებულ კვლევაში „ToxicSkills“ ClawHub-სა და skills.sh-დან აღებული 3 984 skill გადაამოწმა. შედეგები:

| აღმოჩენა | რაოდენობა |
|---|---|
| გადამოწმებული skill | 3 984 |
| მინიმუმ ერთი უსაფრთხოების პრობლემით | 1 467 (36,82 პროცენტი) |
| მინიმუმ ერთი კრიტიკული პრობლემით | 534 (13,4 პროცენტი) |
| დადასტურებული მავნე დატვირთვა | 76 |

ანგარიშის მიხედვით, skills.sh-ის მონაცემები მხოლოდ ამ საიტის შერჩეულ პირველ 100 skill-ს მოიცავს, სრული ბაზრის ციფრები კი ClawHub-ს ეხება. დაფიქსირებულ თავდასხმის ტიპებს შორისაა დაყენების ინსტრუქციები, რომლებიც მომხმარებელს არასანდო პროგრამის გადმოწერასა და გაშვებას აიძულებს, დამალული (Base64-ით ან Unicode-ით შენიღბული) ბრძანებები, რომლებიც ავტორიზაციის მონაცემებს თავდამსხმელს უგზავნის, ასევე უსაფრთხოების შემოწმებების გამორთვისა და უკანა კარის დაყენების მცდელობები. დადასტურებული მავნე skill-ების 91 პროცენტში გამოყენებულია პრომპტ-ინჟექცია (prompt injection).

> **იცოდი?** Claude-ის დახმარების ცენტრის მიხედვით, Enterprise ორგანიზაციებს შეუძლიათ ჩართონ skill-ების სკანირება, რომელიც ატვირთულ skill-ებსა და დანამატებს მავნე შინაარსზე ამოწმებს. თუმცა ეს უსაფრთხოების ბადეა და წაკითხვას არ ანაცვლებს. იმის გასაგებად, რას აკეთებს skill, საუკეთესო გზა დაყენებამდე მისი SKILL.md-ისა და სკრიპტების თავად გახსნა და წაკითხვაა.

## შემოწმების სია დაყენებამდე

პრაქტიკული სია, რომელიც დოკუმენტაციის რჩევებიდან და რეალური აღმოჩენებიდან გამოვიტანეთ:

1. **გადაამოწმე წყარო.** ვისია რეპოზიტორია? ოფიციალური კომპანიის ან ცნობილი დეველოპერის, თუ ცნობილ პაკეტს ძალიან დაემსგავსებული ასლია (typosquatting)?
2. **წაიკითხე SKILL.md თავიდან ბოლომდე.** ფრაზები, როგორიცაა „ჯერ ეს გადმოწერე და გაუშვი“, „გამორთე უსაფრთხოების პარამეტრი“, „გაგზავნე ამ მისამართზე“, განგაშის ნიშანია.
3. **შეამოწმე scripts/ საქაღალდე.** თუ არის ხაზები, რომელთა წაკითხვა არ შეგიძლია, დამალული ან Base64-ით დაშიფრული, ნუ დააყენებ.
4. **შეამოწმე გარე ბმულები.** თუ skill ვებ მისამართიდან ინსტრუქციებს ან მონაცემებს იღებს, გახსოვდეს, რომ ეს შინაარსი ნებისმიერ დროს შეიძლება შეიცვალოს.
5. **დააყენე ის, რაც გჭირდება.** „ყველაფერის დაყენების“ ნაცვლად skill-ების ერთ-ერთად არჩევა როგორც კონტექსტს, ისე თავდასხმის ზედაპირს ამცირებს.

## მინიმალური უფლებები და საიდუმლო გასაღებები

მნიშვნელოვანია, სად მუშაობს skill. Claude-ის დოკუმენტაციით, Claude API გარემოში skill-ებს ქსელზე წვდომა არ აქვთ და გაშვების დროს პაკეტებს ვერ აყენებენ. claude.ai-ზე ქსელზე წვდომა მომხმარებლისა და ადმინისტრატორის პარამეტრების მიხედვით სრული, ნაწილობრივი ან გამორთული შეიძლება იყოს. Claude Code-ში კი skill-ებს ქსელზე იმდენივე წვდომა აქვთ, რამდენიც შენს კომპიუტერში არსებულ ნებისმიერ პროგრამას. ანუ ლოკალურ აგენტში დაყენებული skill შენი უფლებებით მუშაობს.

ამიტომ მინიმალური უფლებების პრინციპი კრიტიკულია. Claude Code-ში skill-ის frontmatter-ში არსებული allowed-tools ველი უზრუნველყოფს, რომ skill-ის გამოძახებისას გარკვეული ინსტრუმენტები ნებართვის თხოვნის გარეშე გამოიყენებოდეს. დოკუმენტაციის მიხედვით, ეს ნებართვა შემდეგი შეტყობინებისას ნულდება. მაინც, თუ სხვის დაწერილ skill-ში ფართო ნებართვებს ხედავ, კარგი ჩვევაა, ცნობიერი დადასტურების გარეშე არ დააყენო.

საიდუმლო გასაღებების წესი მარტივია: API გასაღებები, პაროლები და წვდომის ტოკენები არასოდეს ჩაწერო SKILL.md-ში ან skill-ის საქაღალდეში. როცა skill-ს გააზიარებ ან რეპოზიტორიაში ატვირთავ, ამ საქაღალდეში არსებული ყველაფერიც გაჰყვება. გასაღებები შეინახე გარემოს ცვლადებში ან გამოყენებული ინსტრუმენტის უსაფრთხო საავტორიზაციო მონაცემების საცავში, skill-ს კი მხოლოდ ის აუხსენი, როგორ მიუწვდეს მათზე ხელი.

2026 წლის ოქტომბრის მდგომარეობით, skill-ების ეკოსისტემა ძალიან სწრაფად იზრდება და ეს ზრდა აპლიკაციების მაღაზიების პირველი წლების უსაფრთხოების პრობლემებს გვახსენებს. კარგი ამბავი ის არის, რომ skill-ის წაკითხვა აპლიკაციის საწყისი კოდის წაკითხვაზე ბევრად მარტივია, რადგან უმეტესი ნაწილი უბრალო ტექსტია.

შენ skill-ს დაყენებამდე ხსნი და კითხულობ, თუ ვარსკვლავების რაოდენობასა და ჩამოტვირთვების ციფრს ენდობი?
