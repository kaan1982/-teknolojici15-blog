ხელოვნური ინტელექტის ასისტენტებმა ყველაფერი ცოტ-ცოტას იციან, მაგრამ არ იციან შენი კომპანიის ანგარიშის შაბლონი, შენი ბრენდის ფერები ან ფაილის რომელიმე ტიპთან სწორად მუშაობის ხრიკები. რომ შეგეძლოს ეს ყოველ საუბარში დიდხანს ახსნის ნაცვლად ერთხელ დაგეფასოებინა და აგენტისთვის გეთქვა „საჭიროებისას გამოიყენე“? სწორედ ეს არის „skill“ (უნარი) იდეა.

## მოკლედ: ერთი საქაღალდე და ერთი SKILL.md

Anthropic-ის განმარტებით, Agent Skills არის მოდულური პაკეტები, რომლებიც Claude-ის შესაძლებლობებს აფართოებს. თითოეული skill ერთად აერთიანებს ინსტრუქციებს, მეტამონაცემებსა და სურვილისამებრ რესურსებს (სკრიპტები, შაბლონები), და Claude მათ თავისით იყენებს, როცა ისინი რელევანტურია. Anthropic-ის საინჟინრო ბლოგი კიდევ უფრო მარტივად ამბობს: skill-ები არის „ორგანიზებული საქაღალდეები ინსტრუქციებით, სკრიპტებითა და რესურსებით“, რომლებსაც აგენტი კონკრეტულ საქმეებში უკეთესობისთვის საჭიროებისას ტვირთავს.

ტექნიკურად, skill არის საქაღალდე, რომელშიც მინიმუმ SKILL.md ფაილია. ამ ფაილის დასაწყისში YAML ფორმატით ორი სავალდებულო ველია: name (სახელი) და description (აღწერა). მის ქვემოთ კი მარტივი Markdown-ით დაწერილი ინსტრუქციებია. საქაღალდეში სურვილის შემთხვევაში შეგიძლია დაამატო ქვესაქაღალდეები, როგორიცაა scripts/ (გასაშვები კოდი), references/ (დამატებითი დოკუმენტები) და assets/ (შაბლონი, სურათი, მონაცემები).

Anthropic ამ სტრუქტურას ადარებს ახალი თანამშრომლისთვის მომზადებულ ადაპტაციის გზამკვლევს. გზამკვლევს მაგიდაზე დებ, თანამშრომელი კი საჭიროებისას გახსნის და ჩახედავს.

## საიდუმლო: ყველაფერი ერთდროულად არ იტვირთება

Skill-ებს ჩვეულებრივი გრძელი პრომპტისგან განასხვავებს დიზაინი, რომელსაც „ეტაპობრივი გახსნა“ (progressive disclosure) ჰქვია. Claude-ის დოკუმენტაციით, შინაარსი სამ დონედ იტვირთება:

| დონე | როდის იტვირთება? |
|---|---|
| 1. მეტამონაცემები (სახელი + აღწერა) | ყოველთვის, დასაწყისში (თითო skill-ზე დაახლოებით 100 ტოკენი) |
| 2. SKILL.md-ის ძირითადი ტექსტი | როცა skill ამოქმედდება (რეკომენდებულია 5 000 ტოკენზე ნაკლები) |
| 3. დამატებითი ფაილები და სკრიპტები | მხოლოდ საჭიროებისას; სკრიპტებიდან კონტექსტში მხოლოდ მათი გამოსავალი შედის |

ამგვარად აგენტში შეგიძლია ათობით skill ჩატვირთო, მაგრამ ისინი კონტექსტის ფანჯარას ვერ შეავსებენ. ამოქმედებამდე თითოეული skill-იდან „მაგიდაზე“ მხოლოდ მისი სახელი და აღწერა დევს. დოკუმენტაციის მაგალითში PDF skill ფორმების შევსების ინსტრუქციებს ცალკე forms.md ფაილში ინახავს, და Claude ამ ფაილს მხოლოდ მაშინ კითხულობს, როცა ფორმას მართლა ავსებს.

> **იცოდი?** Anthropic-მა Agent Skills 2025 წლის 16 ოქტომბერს გამოაცხადა, ხოლო 2025 წლის 18 დეკემბერს ფორმატი agentskills.io-ზე ღია სტანდარტად გამოაქვეყნა. ამიტომ 2026 წლის ოქტომბრის მდგომარეობით იგივე SKILL.md სტრუქტურას სხვა ინსტრუმენტების, მაგალითად GitHub Copilot-ისა და OpenAI Codex-ის, დოკუმენტაციაშიც ნახავ. Copilot-ის დოკუმენტაცია skill-ების შესამოწმებლად პირდაპირ agentskills.io-ს სპეციფიკაციაზე გადაგიყვანს.

## პრომპტი, MCP, დანამატი: რა განსხვავებაა?

ეს ცნებები ხშირად ერევათ, რადგან ყველა „აგენტის გაუმჯობესებას“ ეხება. Claude-ის დახმარების ცენტრის დაყოფა ასე შეიძლება შეჯამდეს:

- **პრომპტი ან მორგებული ინსტრუქციები:** ზოგადი მითითებები, რომლებიც ყველა ან კონკრეტულ საუბარში მოქმედებს. Skill კი კონკრეტულ დავალებაზეა მორგებული და მხოლოდ მაშინ ირთვება, როცა რელევანტურია.
- **პროექტები:** მუდმივი ფონური ინფორმაცია, რომელიც პროექტის შიგნით ყველა საუბარში ყოველთვის ჩატვირთულია. Skill კი პროცედურაა, რომელიც საჭიროებისას იხსნება.
- **MCP (Model Context Protocol) კონექტორები:** Claude-ს გარე სერვისებსა და მონაცემთა წყაროებს აკავშირებს. ანუ „წვდომას“ იძლევა. Skill კი ამ წვდომის გამოყენების „მეთოდის ცოდნაა“. დახმარების ცენტრი ამბობს, რომ ისინი ხშირად ერთად გამოიყენება.
- **დანამატები (plugin):** Claude Code-სა და Cowork-ში დანამატი რამდენიმე ნაწილის (skill-ები, კონექტორები, ბრძანებები, ქვეაგენტები) ერთად გავრცელების პაკეტია. OpenAI-ს დოკუმენტაციაც ანალოგიურ დაყოფას აკეთებს: skill არის წერის ფორმატი, დანამატი კი გავრცელების ფორმა.

მოკლედ, MCP აგენტს ხელს აძლევს, skill ამ ხელს უნარს ასწავლის, დანამატი კი ყველაფერს ერთ ყუთში აწვდის.

## სად მუშაობს?

2026 წლის ოქტომბრის მდგომარეობით, Claude-ის დოკუმენტაციის მიხედვით, skill-ები ხელმისაწვდომია Claude-ის აპლიკაციებში (claude.ai), Claude Code-სა და Claude API-ში კოდის გაშვების ინსტრუმენტთან ერთად. დახმარების ცენტრი აღნიშნავს, რომ skill-ები Free, Pro, Max, Team და Enterprise გეგმებში მოიპოვება და მათთვის კოდის გაშვების ფუნქცია უნდა იყოს ჩართული.

მნიშვნელოვანი დეტალი: მორგებული skill-ები სხვადასხვა გარემოს შორის არ სინქრონიზდება. claude.ai-ზე ატვირთული skill მხოლოდ შენს ანგარიშზეა. API-ზე ატვირთული skill მთელ სამუშაო სივრცეს ეზიარება. Claude Code-ში კი ის პირად (~/.claude/skills/) ან პროექტის საქაღალდეში (.claude/skills/) ინახება.

უსაფრთხოების საკითხიც არსებობს. რადგან skill-ებს კოდის გაშვება შეუძლიათ, დოკუმენტაცია გვირჩევს, მათ „პროგრამის დაყენებასავით“ მოვეპყროთ და მხოლოდ სანდო წყაროებიდან გამოვიყენოთ. ამას სერიის ბოლო სტატიაში ცალკე განვიხილავთ.

ამ განყოფილების შემდეგ სტატიებში ეტაპობრივად დავწერთ საკუთარ skill-ს და კატეგორიების მიხედვით განვიხილავთ რეალურად არსებულ, სასარგებლო skill-ებს.

რომელი საქმე, რომელსაც ყოველდღე ხელოვნურ ინტელექტს ისევ და ისევ უხსნი და ამბობ „ნეტა ამას ერთხელ ვასწავლო“, შენთვის რომელია?
