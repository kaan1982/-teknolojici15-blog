सॉफ्टवेयर बनाने वाले के लिए skills दो कारणों से दिलचस्प हैं। पहला, ऐसे "निर्माता" skills हैं जो आपको अपने skills ज़्यादा तेज़ी से और मापने योग्य ढंग से लिखने में मदद करते हैं। दूसरा, ऐसे पैकेज हैं जो एजेंट को इंजीनियरिंग का अनुशासन (परीक्षण, योजना, डीबगिंग) देते हैं। इस लेख में हम दोनों को देखते हैं, सिर्फ उन उदाहरणों के साथ जिनका अस्तित्व हमने पुष्ट किया है।

## skill-creator: skill लिखने वाला skill

Anthropic की आधिकारिक anthropics/skills रिपॉज़िटरी का skill-creator नए skills बनाने, मौजूदा skills को संपादित करके सुधारने और उनके प्रदर्शन को मापने के लिए डिज़ाइन हुआ है। उसके विवरण के अनुसार वह मूल्यांकन (eval) चलाने, नतीजों की प्रसरण विश्लेषण से तुलना करने और skill के विवरण को बेहतर सक्रियता के लिए अनुकूलित करने का काम भी संभालता है।

कार्यप्रवाह काफ़ी मानवीय ढंग से बताया गया है: तय करें कि आप क्या चाहते हैं, मसौदा लिखें, कुछ परीक्षण संदेश तैयार करें, skill वाले Claude को इन संदेशों के साथ चलाएँ, नतीजों का साथ मिलकर मूल्यांकन करें, दोबारा लिखें, दोहराएँ। फ़ोल्डर में मूल्यांकन चलाने, तुलना रिपोर्ट बनाने और विवरण सुधारने वाली अलग स्क्रिप्ट हैं, और नतीजों को दृश्य रूप से देखने के लिए एक "eval-viewer" भी है।

agentskills.io की विवरण अनुकूलन गाइड भी इस skill को उदाहरण बनाती है। गाइड के अनुसार skill-creator इस चक्र को शुरू से अंत तक स्वचालित करता है: परीक्षण समूह को बाँटता है, सक्रियता दरों को समानांतर रूप से मापता है, Claude के साथ विवरण सुधार सुझाता है और एक लाइव HTML रिपोर्ट बनाता है।

> **क्या आप जानते थे?** agentskills.io का सुझाया सक्रियता परीक्षण लगभग 20 नमूना संदेश इस्तेमाल करता है और हर एक को 3 बार चलाता है। यानी एक अकेले विवरण को आज़माने का मतलब 60 रन। ओवरफ़िटिंग से बचने के लिए संदेशों का लगभग 60 प्रतिशत सुधार के लिए और 40 प्रतिशत सिर्फ सत्यापन के लिए रखा जाता है। गाइड कहती है कि अक्सर पाँच दौर काफ़ी होते हैं।

## mcp-builder और claude-api: इंटीग्रेशन बनाने वालों के लिए

- **mcp-builder (आधिकारिक):** बड़े भाषा मॉडलों को अच्छी तरह डिज़ाइन किए औज़ारों के ज़रिए बाहरी सेवाओं से बात करवाने वाले MCP सर्वर विकसित करने की गाइड। यह Python (FastMCP) या Node/TypeScript (MCP SDK) के साथ चलती है। Skill प्रक्रिया को चार चरणों में बाँटता है: शोध और योजना, क्रियान्वयन, समीक्षा और परीक्षण, मूल्यांकन बनाना। फ़ोल्डर में भाषा-आधारित संदर्भ दस्तावेज़ और मूल्यांकन स्क्रिप्ट हैं।
- **claude-api (आधिकारिक):** Claude API और Anthropic SDK के लिए संदर्भ skill। इसमें मॉडल आईडी, पैरामीटर, स्ट्रीमिंग, टूल उपयोग, कैशिंग जैसे विषय आते हैं और कई प्रोग्रामिंग भाषाओं के लिए अलग फ़ोल्डर हैं। Claude के दस्तावेज़ों के अनुसार यह ओपन सोर्स skill Claude Code के साथ आता है।
- **webapp-testing (आधिकारिक):** स्थानीय वेब ऐप्स को Playwright से परखने का टूलसेट। फ़्रंट-एंड विकसित करने वालों के लिए एक व्यावहारिक सहायक, जिसका ज़िक्र हमने डिज़ाइन वाले लेख में भी किया।

## समुदाय से: Superpowers के साथ इंजीनियरिंग अनुशासन

आधिकारिक रिपॉज़िटरी के बाहर डेवलपरों में सबसे ज़्यादा चर्चित पैकेजों में से एक Jesse Vincent की MIT लाइसेंस वाली obra/superpowers रिपॉज़िटरी है। यह खुद को कोडिंग एजेंटों के लिए "सॉफ्टवेयर विकास की संपूर्ण पद्धति" बताती है। अक्टूबर 2026 तक रिपॉज़िटरी में ये skills हैं (चयन):

| Skill | कब सक्रिय होता है? |
|---|---|
| brainstorming | कोई नई सुविधा या रचनात्मक काम शुरू करने से पहले |
| writing-plans | कई चरणों वाले काम के लिए, कोड को छूने से पहले योजना लिखते समय |
| test-driven-development | क्रियान्वयन के दौरान: पहले विफल परीक्षण, फिर कम से कम कोड |
| systematic-debugging | किसी गलती या विफल परीक्षण से सामना होने पर, सुधार सुझाने से पहले |
| verification-before-completion | "हो गया" कहने से पहले सत्यापन कमांड चलाने के लिए |

रिपॉज़िटरी की README Claude Code के साथ Codex, Cursor, Gemini CLI और GitHub Copilot CLI जैसे कई एजेंटों के लिए इंस्टॉल निर्देश देती है और बताती है कि Claude Code की ओर यह Anthropic के आधिकारिक प्लगइन मार्केटप्लेस में मौजूद है। यह Agent Skills के खुले मानक होने का व्यावहारिक नतीजा है: वही skill अलग-अलग टूलों में चल सकता है।

## दूसरे प्लेटफ़ॉर्मों पर भी वही विचार

OpenAI के ChatGPT और Codex दस्तावेज़ भी skills को "खुले agent skills मानक" पर आधारित बताते हैं। अक्टूबर 2026 तक दस्तावेज़ों में दो अंतर्निहित सहायक सामने आते हैं: आपके बताए काम से skill बनाने वाला skill-creator (Codex में $skill-creator से बुलाया जाता है) और openai/skills रिपॉज़िटरी या दूसरी रिपॉज़िटरी से तैयार skills इंस्टॉल करने वाला skill-installer। Codex स्थानीय skills को प्रोजेक्ट और उपयोगकर्ता स्तर के .agents/skills फ़ोल्डरों से पढ़ता है।

एक डेवलपर के लिए सबसे कीमती आदत शायद यह हो: जो भी लंबा स्पष्टीकरण आप दोहराते हैं, अपनी कोड समीक्षा चेकलिस्ट या डिप्लॉयमेंट चरणों को एक skill में बदलकर प्रोजेक्ट की रिपॉज़िटरी में रख दें। Claude Code में .claude/skills फ़ोल्डर में रखे skills रिपॉज़िटरी के साथ टीम तक भी पहुँचते हैं। पर आप जो भी समुदाय का skill इंस्टॉल करें, उसकी स्क्रिप्ट पढ़ना न भूलें, क्योंकि ये skills आपके कंप्यूटर पर आपके अधिकारों के साथ कोड चला सकते हैं।

आपकी विकास प्रक्रिया में कौन-सा चरण सबसे ज़्यादा यह सोचने पर मजबूर करता है कि "काश इसके लिए कोई skill होता": परीक्षण, कोड समीक्षा या डिप्लॉयमेंट?
