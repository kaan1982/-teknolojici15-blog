Для людини, що розробляє програмне забезпечення, скіли цікаві з двох боків. По-перше, є «генеративні» скіли, які допомагають писати власні скіли швидше й вимірювано. По-друге, є пакети, що дають агентові інженерну дисципліну (тестування, планування, налагодження). У цій статті ми розглядаємо обидва, лише на прикладах, існування яких перевірили.

## skill-creator: скіл, що пише скіли

skill-creator з офіційного репозиторію Anthropic anthropics/skills призначений для створення нових скілів, редагування й покращення наявних та вимірювання їхньої продуктивності. За його описом, він бере на себе і запуск оцінювань (eval), порівняння результатів за допомогою аналізу дисперсії та оптимізацію опису скіла, щоб той краще спрацьовував.

Процес описаний досить по-людськи: вирішіть, чого хочете, напишіть чернетку, підготуйте кілька тестових повідомлень, запустіть Claude зі скілом на цих повідомленнях, оцініть результати разом, перепишіть, повторіть. У папці є окремі скрипти, що запускають оцінювання, створюють порівняльні звіти та покращують опис, а також «eval-viewer» для візуального огляду результатів.

Посібник agentskills.io з оптимізації опису теж наводить цей скіл як приклад. За посібником, skill-creator автоматизує цей цикл від початку до кінця: розділяє тестовий набір, паралельно вимірює частоту спрацьовування, пропонує разом із Claude покращення опису та створює живий HTML-звіт.

> **Чи знаєте ви?** У тесті спрацьовування, який рекомендує agentskills.io, використовується близько 20 прикладів повідомлень, і кожне запускається по 3 рази. Тобто випробування одного опису це 60 запусків. Щоб уникнути перенавчання (overfitting), приблизно 60% повідомлень відводиться для покращення, а 40% лише для перевірки. Посібник каже, що найчастіше вистачає п'яти раундів.

## mcp-builder і claude-api: для тих, хто будує інтеграції

- **mcp-builder (офіційний):** посібник з розробки MCP-серверів, що дозволяють великим мовним моделям добре взаємодіяти із зовнішніми сервісами через продумані інструменти. Працює з Python (FastMCP) або Node/TypeScript (MCP SDK). Скіл ділить процес на чотири етапи: дослідження й планування, реалізація, огляд і тестування, створення оцінювань. У папці є довідкові документи за мовами та скрипти оцінювання.
- **claude-api (офіційний):** довідковий скіл для Claude API та SDK Anthropic. Охоплює ідентифікатори моделей, параметри, потокову передачу (streaming), використання інструментів, кешування тощо й містить окремі папки для багатьох мов програмування. За документацією Claude, цей скіл із відкритим кодом постачається разом із Claude Code.
- **webapp-testing (офіційний):** набір інструментів для тестування локальних вебзастосунків за допомогою Playwright. Практичний помічник для тих, хто розробляє фронтенд, про якого ми згадували і в статті про дизайн.

## Від спільноти: Superpowers та інженерна дисципліна

Поза офіційним репозиторієм один із найобговорюваніших серед розробників пакетів це репозиторій obra/superpowers Джессі Вінсента під ліцензією MIT. Він описує себе як «повну методологію розробки програмного забезпечення» для кодувальних агентів. Станом на жовтень 2026 року в репозиторії є такі скіли (добірка):

| Скіл | Коли вмикається? |
|---|---|
| brainstorming | Перед початком нової функції чи творчої роботи |
| writing-plans | Коли пишете план для багатокрокової роботи, не торкаючись коду |
| test-driven-development | Під час реалізації: спершу тест, що падає, потім мінімум коду |
| systematic-debugging | Коли стикаєтеся з помилкою чи тестом, що не проходить, до того як пропонувати виправлення |
| verification-before-completion | Щоб запустити команди перевірки, перш ніж сказати «готово» |

У README репозиторію є інструкції зі встановлення для багатьох агентів, як-от Codex, Cursor, Gemini CLI і GitHub Copilot CLI, окрім Claude Code, і зазначено, що для Claude Code він є в офіційному маркетплейсі плагінів Anthropic. Це практичний наслідок того, що Agent Skills є відкритим стандартом: той самий скіл може працювати в різних інструментах.

## Така сама ідея на інших платформах

Документація OpenAI щодо ChatGPT і Codex також описує скіли як побудовані на «відкритому стандарті agent skills». Станом на жовтень 2026 року в документації виділяються два вбудовані помічники: skill-creator, що створює скіл за описаною вами роботою (у Codex викликається через $skill-creator), та skill-installer, що встановлює готові скіли з репозиторію openai/skills або інших репозиторіїв. Codex читає локальні скіли з папок .agents/skills на рівні проєкту і користувача.

Для розробника найцінніша звичка, можливо, така: перетворювати кожне довге пояснення, яке ви повторюєте, свій контрольний список код-рев'ю чи кроки розгортання на скіл і класти його в репозиторій проєкту. Скіли, покладені в Claude Code в папку .claude/skills, потрапляють і до команди разом із репозиторієм. Але не забувайте читати скрипти кожного встановленого скіла зі спільноти, бо вони можуть виконувати код на вашому комп'ютері з вашими правами.

Який крок у вашому процесі розробки найчастіше змушує сказати «шкода, що немає скіла»: тестування, код-рев'ю чи розгортання?
