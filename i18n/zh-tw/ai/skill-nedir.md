人工智慧助理什麼都懂一點，但不知道你們公司的報告範本、你品牌的顏色，或是正確處理某種檔案類型的訣竅。與其在每次對話中冗長地解釋，如果你能打包一次，然後對代理說「需要時就用它」呢？「技能」（skill）正是這個想法。

## 簡單說：一個資料夾與一個 SKILL.md

依 Anthropic 的定義，Agent Skills 是擴充 Claude 能力的模組化套件。每個技能把指示、中繼資料和可選資源（腳本、範本）放在一起，Claude 會在相關時自動使用它們。Anthropic 的工程部落格說得更簡潔：技能是代理為了在特定工作上更出色，在需要時載入的「經過整理的指示、腳本與資源資料夾」。

技術上，技能至少是一個裡面有名為 SKILL.md 檔案的資料夾。這個檔案開頭有 YAML 格式的兩個必填欄位：name（名稱）和 description（說明）。下面則是用純 Markdown 寫成的指示。你還可以在資料夾中加入 scripts/（可執行程式碼）、references/（補充文件）和 assets/（範本、圖像、資料）等子資料夾。

Anthropic 把這個結構比作為新進員工準備的到職指南。你把指南放在桌上，員工需要時會翻開來看。

## 祕訣：並非一次全部載入

把技能與一般的長提示詞區分開來的，是稱為「漸進式載入」（progressive disclosure）的設計。依 Claude 的文件，內容分三層載入：

| 層級 | 何時載入？ |
|---|---|
| 1. 中繼資料（名稱 + 說明） | 隨時，在啟動時（每個技能約 100 個 token） |
| 2. SKILL.md 內文 | 技能被觸發時（建議在 5,000 個 token 以下） |
| 3. 附加檔案與腳本 | 僅在需要時；只有腳本的輸出會進入脈絡 |

這樣你可以替代理載入幾十個技能，卻不會把所有東西都塞滿脈絡視窗（context window）。在被觸發之前，每個技能只有名稱和說明「擺在桌上」。文件中的範例裡，PDF 技能把填寫表單的指示放在獨立的 forms.md 檔案，Claude 只有在真的要填表單時才讀這個檔案。

> **你知道嗎？** Anthropic 在 2025 年 10 月 16 日宣布了 Agent Skills，並在 2025 年 12 月 18 日把這個格式作為開放標準發布在 agentskills.io。因此到 2026 年 10 月，你在 GitHub Copilot 和 OpenAI Codex 等其他工具的文件中，也能看到同樣的 SKILL.md 結構。Copilot 的文件直接引導查看 agentskills.io 規格來檢查技能。

## 提示詞、MCP、外掛：有什麼差別？

這幾個概念常被搞混，因為它們都與「讓代理變得更好」有關。Claude 說明中心的區分可以概括如下：

- **提示詞或自訂指示：** 在每次對話或所有對話中都適用的一般性引導。技能則是針對特定任務，且只在相關時才啟動。
- **專案（Projects）：** 在專案內的對話中，永遠載入的固定背景知識。技能則是需要時才打開的程序。
- **MCP（Model Context Protocol）連接器：** 把 Claude 連接到外部服務與資料來源。也就是提供「存取」。技能則是說明如何使用那個存取的「方法知識」。說明中心表示兩者經常一起使用。
- **外掛（plugin）：** 在 Claude Code 和 Cowork 方面，外掛是把多個部分（技能、連接器、指令、子代理）一起散布的套件。OpenAI 的文件也做了類似的區分：技能是撰寫格式，外掛則是散布方式。

簡而言之，MCP 給代理一雙手，技能教這雙手本事，外掛則把它們裝在一個盒子裡交付。

## 在哪裡運作？

截至 2026 年 10 月，根據 Claude 的文件，技能可以在 Claude 應用程式（claude.ai）、Claude Code，以及搭配程式碼執行工具的 Claude API 中使用。說明中心表示，技能在 Free、Pro、Max、Team 和 Enterprise 方案中提供，且需要開啟程式碼執行功能。

一個重要的細節：自訂技能不會在不同介面之間同步。你上傳到 claude.ai 的技能只屬於你的帳號。上傳到 API 的技能則與整個工作區共用。在 Claude Code 中，則是放在個人資料夾（~/.claude/skills/）或專案資料夾（.claude/skills/）。

還有一個安全面向。由於技能可以執行程式碼，文件建議「像安裝軟體一樣」對待它們，並只使用來自可信來源的技能。我們會在系列的最後一篇另外談這一點。
