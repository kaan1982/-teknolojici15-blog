寫一個技能不必是程式設計師。最簡單的形式，只需要一個資料夾，裡面放一個文字檔。但一個運作良好的技能與一個從不被觸發的技能之間的差別，往往就藏在一句話裡：說明。在這篇文章裡，我們從零開始寫一個小而真實的技能。

## 步驟 1：建立資料夾與 SKILL.md

根據 Agent Skills 規格，技能是至少包含一個 SKILL.md 檔案的資料夾。檔案最開頭是 YAML 前置資料（frontmatter），有兩個必填欄位：

- **name：** 最多 64 個字元。只能用小寫字母、數字和連字號。不能以連字號開頭或結尾，不能包含連續兩個連字號，而且必須與資料夾名稱相同。Claude 的文件還指出，名稱中不能使用「anthropic」和「claude」這兩個字。
- **description：** 不可為空，最多 1,024 個字元。必須說明技能做什麼、何時使用。

另外也有選用欄位（license、compatibility、metadata 以及實驗性的 allowed-tools），但大多數技能用不到。

## 步驟 2：用心撰寫說明

為什麼說明這麼重要？因為代理一開始只會讀取每個技能的名稱和說明。用 agentskills.io 的話說，觸發的「全部重擔」都落在說明身上。如果說明沒有講清楚這個技能何時有用，代理就不會去碰它。

各資料來源的建議可以概括如下：

- 同時寫出**做什麼**和**何時使用**。
- Claude 的文件建議說明用**第三人稱**撰寫，因為說明會被加入系統提示詞（「處理 Excel 檔案」，而不是「我可以幫你」）。
- agentskills.io 建議也明確列出使用者沒有點名該領域的情況。
- 保持簡短：幾句話，頂多一小段。Claude Code 在清單中會把說明截斷在 1,536 個字元，所以最重要的使用情境要放在前面。

## 步驟 3：內容簡短，腳本要聰明

舉個例子，想想一個符合本部落格自身寫作規則的技能：文中不要留下長破折號（em dash）和短破折號（en dash）。資料夾結構如下：

```
tire-denetimi/
├── SKILL.md
└── scripts/
    └── tire_bul.py
```

而 SKILL.md 檔案就只有這麼多：

```markdown
name: tire-denetimi
description: 找出部落格文章中使用長破折號（U+2014）和短破折號（U+2013）的地方，並建議修正。當使用者準備發布 Markdown 文章，說「檢查破折號」、「有沒有符合寫作規則」，或沒有點名但想在發布前做最後檢查時使用。

# 破折號檢查

1. 執行 `python scripts/tire_bul.py <dosya.md>` 指令。
2. 對輸出中的每一行，建議以句號、逗號、冒號或括號取代破折號。
3. 不要改變原意。對沒把握的行，詢問使用者。
4. 最後用一句話報告修正了幾行。
```

Claude 的文件把脈絡視窗（context window）視為「共用資源」，建議只加入模型原本不知道的資訊。內容應該保持在 500 行以內。較長的參考文字應移到獨立檔案，並從 SKILL.md 以單層方式連結到這些檔案。

關於腳本的規則也很明確：「自己解決，別把問題丟出去」。也就是說，腳本應該自己處理錯誤情況，不該以「讓它炸掉，Claude 會想辦法」的心態來寫。腳本執行時，進入脈絡的不是程式碼本身，而只有它的輸出。這讓腳本在重複且不容出錯的工作上，比文字指示更可靠。

> **你知道嗎？** 在 Claude Code 中，舊的「自訂斜線指令」已經與技能合併。.claude/commands/deploy.md 檔案和 .claude/skills/deploy/SKILL.md 會建立同一個 /deploy 指令。如果你不想讓某個技能自動觸發，可以在 frontmatter 加上 disable-model-invocation: true，只讓它被手動呼叫。

## 步驟 4：測試，然後再測試

Claude 的最佳實踐指南建議，在寫長篇文件之前先準備評估情境，發布前的檢查清單中包括至少三項評估，以及分別在 Haiku、Sonnet 和 Opus 模型上測試。理由很簡單：在 Opus 上運作完美的指示，對 Haiku 可能需要更多細節。

要測試觸發情形，agentskills.io 的建議很具體：準備大約 20 則範例使用者訊息。其中 8 到 10 則應該觸發技能，8 到 10 則不該觸發。最有價值的反面範例是「差一點就中」的，也就是用了相同字詞、卻要求別的工作的訊息。由於模型的行為每次不盡相同，建議每則訊息執行數次（一開始 3 次），看觸發率。

| 不好的說明 | 好的說明 |
|---|---|
| 「協助處理 PDF。」 | 說明做什麼、何時使用 |
| 只有技術細節 | 說明使用者的意圖 |
| 什麼都涵蓋 | 也說明不做什麼 |

安裝也很簡單：在 Claude Code 中，把資料夾放在 ~/.claude/skills/ 底下（個人用），或專案的 .claude/skills/ 資料夾即可。Claude Code 會監看這些資料夾，並在同一個工作階段中偵測變更，不需要重新啟動。在 claude.ai，則可以從設定把技能以 zip 上傳。
