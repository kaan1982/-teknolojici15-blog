讓技能如此強大的原因，同時也讓它們有風險：技能攜帶的不只是文字，還可以是可執行的程式碼。代理載入那個技能時，會把裡面的指示當作自己的指示來遵循，並且可以執行其中的腳本。因此，Claude 文件的建議可以用一句話概括：把安裝技能當成安裝軟體。

## 官方資料怎麼說？

Claude 文件中的安全章節相當直接。它建議你只使用來自可信來源的技能，也就是你自己寫的或來自 Anthropic 的。如果你不得不使用來自未知來源的技能，它要求你「格外小心」，並在使用前徹底稽核。

Anthropic 的工程文章也是同樣的調性：對於來自較不可信來源的技能，建議檢查打包的檔案，特別是程式碼相依套件和腳本，並檢查指示連接外部網路的內容。文件還特別強調一項風險：從外部網址取得資料的技能是危險的，因為取得的內容可能含有惡意指示。

## 現場發生了什麼事？

這些警告不是紙上談兵。資安公司 Snyk 在 2026 年 2 月 5 日發表的「ToxicSkills」研究中，掃描了來自 ClawHub 和 skills.sh 的 3,984 個技能。結果如下：

| 發現 | 數量 |
|---|---|
| 掃描的技能 | 3,984 |
| 至少有一個安全問題 | 1,467（36.82%） |
| 至少含有一個嚴重問題 | 534（13.4%） |
| 已證實的惡意載荷 | 76 |

根據報告，skills.sh 的資料只涵蓋該網站精選的前 100 個技能，完整的市場數字則是針對 ClawHub。所見的攻擊類型包括：引導使用者下載並執行不可信軟體的安裝指示、把憑證傳給攻擊者的隱藏（以 Base64 或 Unicode 偽裝）指令，以及關閉安全檢查和植入後門的企圖。在已證實的惡意技能中，有 91% 使用了提示詞注入（prompt injection）。

> **你知道嗎？** 根據 Claude 說明中心，Enterprise 組織可以開啟技能掃描，檢查已上傳的技能與外掛是否含惡意內容。但這只是一張安全網，不能取代閱讀。要了解一個技能做什麼，最好的辦法，是在安裝前親自打開它的 SKILL.md 和腳本讀一讀。

## 安裝前的檢查清單

這是我們從文件建議和現場發現整理出的實用清單：

1. **確認來源。** 這個儲存庫是誰的？是官方公司或知名開發者，還是和某個知名套件名稱非常相似的仿冒品（typosquatting）？
2. **從頭到尾讀完 SKILL.md。**「先下載並執行這個」、「關閉安全設定」、「傳送到這個位址」之類的說法都是警訊。
3. **檢查 scripts/ 資料夾。** 如果有你讀不懂、被隱藏或以 Base64 編碼的行，就別安裝。
4. **檢查外部連結。** 如果技能從某個網址取得指示或資料，記住那份內容隨時可能改變。
5. **只裝你需要的。** 逐一挑選技能，而不是「全部安裝」，能縮小脈絡也縮小攻擊面。

## 最小權限與機密金鑰

技能在哪裡運作也很重要。根據 Claude 文件，在 Claude API 環境中，技能沒有網路存取權限，執行期間也不能安裝套件。在 claude.ai，網路存取可依使用者與管理員設定，為完整、部分或關閉。而在 Claude Code，技能擁有與你電腦上任何程式相同的網路存取。也就是說，你在本機代理上安裝的技能，是以你的權限在運作。

因此最小權限原則至關重要。在 Claude Code 中，技能 frontmatter 的 allowed-tools 欄位，會讓該技能被呼叫時，特定工具不必詢問許可就能使用。根據文件，這個許可會在你的下一則訊息時重置。即便如此，如果你在別人寫的技能裡看到寬泛的權限，不經過有意識的確認就不安裝，是個好習慣。

對機密金鑰的規則很簡單：永遠不要把 API 金鑰、密碼和存取權杖寫進 SKILL.md 或技能資料夾。當你分享技能或推送到儲存庫時，那個資料夾裡的一切也會跟著出去。把金鑰放在環境變數，或你所用工具的安全憑證儲存方式中，然後只在技能裡說明如何取用它們。

截至 2026 年 10 月，技能生態系成長得非常快，而這種成長讓人想起應用程式商店早年的安全問題。好消息是：讀一個技能，比讀一個應用程式的原始碼容易得多，因為大部分是純文字。

在安裝一個技能之前，你會打開來讀裡面的內容，還是相信星星數和下載量呢？
