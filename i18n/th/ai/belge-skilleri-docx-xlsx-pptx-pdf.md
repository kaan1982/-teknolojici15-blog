การสั่ง AI ว่า "ทำรายงานให้หน่อย" เป็นเรื่องง่าย ที่ยากคือให้รายงานนั้นออกมาเป็นไฟล์ Word หรือ Excel ที่เปิดได้จริง รูปแบบไม่เพี้ยน และสูตรทำงานได้ skill หมวดแรก และอาจเป็นหมวดที่ใช้บ่อยที่สุด ก็คือสิ่งนี้เอง: เอกสารสำนักงาน ในบทความนี้เราพูดถึงเฉพาะ skill ที่ตรวจสอบแล้วว่ามีอยู่จริง

## สี่เสาหลัก: docx, xlsx, pptx, pdf

ตามเอกสารของ Claude Anthropic มี skill เอกสารสำเร็จรูป (pre-built) สี่ตัว ทำงานอยู่เบื้องหลังฟีเจอร์สร้างไฟล์ของ Claude และ Anthropic เผยแพร่ซอร์สโค้ดไว้ในที่เก็บ GitHub anthropics/skills

| Skill | ทำอะไร (จากคำอธิบายทางการ) |
|---|---|
| docx | สร้าง อ่าน แก้ไขเอกสาร Word รวมถึงการจัดรูปแบบและเทมเพลต |
| xlsx | เปิดและแก้ไขสเปรดชีต เพิ่มสูตรและกราฟ ทำความสะอาดข้อมูลที่ยุ่งเหยิง |
| pptx | สร้างงานนำเสนอ แก้ไขสไลด์ อ่านและแยกวิเคราะห์เนื้อหาของ .pptx |
| pdf | ดึงข้อความและตาราง รวมและแยก PDF กรอกฟอร์ม ใส่ลายน้ำ |

คำอธิบายในที่เก็บเขียนค่อนข้าง "คะยั้นคะยอ" ตัวอย่างเช่น คำอธิบายของ skill pptx ระบุให้ใช้เมื่อไฟล์ .pptx เกี่ยวข้องกับงาน ไม่ว่าจะเป็นอินพุตหรือเอาต์พุต "ในทางใดก็ตาม" นี่คือตัวอย่างทางการของกฎ "คำอธิบายคือสิ่งที่เรียก skill" ที่เราเล่าไว้ในบทความก่อนหน้า

## ใช้ได้ที่ไหน?

ณ เดือนตุลาคม 2026 ตามเอกสารของ Claude skill ทั้งสี่ตัวนี้ทำงานอัตโนมัติใน claude.ai เมื่อสร้างเอกสาร และเรียกใช้เป็น skill สำเร็จรูปใน Claude API ได้ด้วย ส่วนใน Claude Code ไม่มี skill เอกสารสำเร็จรูปติดมาในตัว แต่คุณเพิ่มที่เก็บ anthropics/skills เป็นตลาดปลั๊กอินสำหรับ Claude Code แล้วติดตั้งแพ็กเกจ document-skills ได้ ตามคำแนะนำในที่เก็บ ให้เพิ่มตลาดด้วยคำสั่ง /plugin marketplace add anthropics/skills ก่อน แล้วค่อยติดตั้ง document-skills@anthropic-agent-skills

เรื่องใบอนุญาตมีข้อแตกต่างอยู่ skill จำนวนมากในที่เก็บเป็นโอเพนซอร์สภายใต้ Apache 2.0 แต่ skill เอกสารทั้งสี่ตัวเผยแพร่แบบ "ไม่ใช่โอเพนซอร์ส แต่เข้าถึงซอร์สได้" (source-available) หมายความว่าคุณศึกษาโค้ดเพื่อเรียนรู้ได้ แต่ต้องอ่านไฟล์ใบอนุญาตก่อนจะนำไปแจกจ่ายต่อในผลิตภัณฑ์ของคุณอย่างอิสระ

> **รู้หรือไม่?** skill pdf เป็นตัวอย่างในตำราของการโหลดทีละขั้น ตามบทความวิศวกรรมของ Anthropic คำสั่งกรอกฟอร์มถูกแยกออกจาก SKILL.md หลักไปอยู่ในไฟล์ forms.md ต่างหาก และ Claude จะอ่านไฟล์นี้เฉพาะตอนกรอกฟอร์มจริง ๆ เท่านั้น ปัจจุบันในที่เก็บ โฟลเดอร์ pdf มีทั้ง forms.md, reference.md และโฟลเดอร์ scripts

## ตัวช่วยข้างเอกสาร

การสร้างเอกสารไม่ได้จบแค่รูปแบบไฟล์ ในที่เก็บ anthropics/skills ยังมีตัวอย่างทางการอื่นที่เน้นด้านเนื้อหา:

- **doc-coauthoring:** ขั้นตอนทำงานทีละขั้นสำหรับเขียนข้อความที่มีโครงสร้างร่วมกัน เช่น ข้อกำหนดทางเทคนิค ข้อเสนอ และเอกสารการตัดสินใจ พาผ่านการส่งต่อบริบท การแก้ไขซ้ำ ๆ และการตรวจสอบ
- **internal-comms:** รวบรวมแหล่งข้อมูลเพื่อช่วยเขียนข้อความสื่อสารภายใน เช่น รายงานสถานะ อัปเดตสำหรับผู้บริหาร จดหมายข่าวบริษัท และคำถามที่พบบ่อย ในรูปแบบที่บริษัทนิยม ในโฟลเดอร์มีตัวอย่างข้อความด้วย
- **brand-guidelines:** นำสีแบรนด์และตัวอักษรทางการของ Anthropic มาใช้กับงานที่ผลิตออกมา คุณค่าที่แท้จริงคือแสดงให้เห็นว่าจะสร้างแบบเดียวกันให้แบรนด์ของคุณเองได้อย่างไร
- **theme-factory:** มีธีมสีและฟอนต์สำเร็จรูป 10 แบบ ใช้กับสไลด์ เอกสาร รายงาน หรือหน้า HTML ได้ และสร้างธีมใหม่ให้ทันทีถ้าต้องการ

ศูนย์ช่วยเหลือยังกล่าวถึง skill ที่พันธมิตรอย่าง Notion, Figma และ Atlassian เตรียมไว้ให้ทำงานร่วมกับตัวเชื่อม MCP ของตัวเอง ซึ่งมีประโยชน์เมื่อทำงานกับเครื่องมือที่ใช้สร้างเอกสาร (เช่น หน้า Notion)

## ใช้งานจริงอย่างไร?

วิธีที่ได้ผลที่สุดคือรวม skill เอกสารสำเร็จรูปเข้ากับ skill เล็ก ๆ ของคุณเอง ตัวอย่างเช่น skill xlsx รู้วิธีสร้าง Excel ให้ถูกต้อง แต่ไม่รู้ว่าตารางยอดขายรายเดือนของบริษัทคุณควรมีคอลัมน์อะไรบ้าง ถ้าคุณเขียน skill สั้น ๆ ที่อธิบายเรื่องนี้ สอง skill จะทำงานร่วมกันและได้ไฟล์ที่ทั้งรูปแบบถูกต้องและตรงตามมาตรฐานของคุณ

มีข้อควรจำสองข้อ ข้อแรก ที่เก็บ anthropics/skills ระบุชัดว่า skill เหล่านี้มีไว้ "เพื่อการสาธิตและการศึกษา" และพฤติกรรมจริงของ Claude อาจต่างจากการใช้งานที่เห็นที่นี่ ข้อที่สอง skill เอกสารต้องการสภาพแวดล้อมรันโค้ด ตามศูนย์ช่วยเหลือ ต้องเปิดฟีเจอร์รันโค้ดไว้ skill จึงจะทำงานได้

บทความถัดไปเราจะไปที่ฝั่งหน้าจอ: skill ที่สร้างงานออกแบบ ส่วนหน้าบ้าน และเว็บ

คุณเสียเวลากับเอกสารประเภทไหนมากที่สุด: ตาราง งานนำเสนอ หรือรายงาน?
