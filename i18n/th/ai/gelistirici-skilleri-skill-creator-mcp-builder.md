สำหรับคนที่พัฒนาซอฟต์แวร์ skill น่าสนใจสองด้าน ด้านแรก มี skill แบบ "ผู้สร้าง" ที่ช่วยให้คุณเขียน skill ของตัวเองได้เร็วขึ้นและวัดผลได้ ด้านที่สอง มีชุด skill ที่ช่วยให้เอเจนต์มีวินัยทางวิศวกรรม (การทดสอบ การวางแผน การแก้บั๊ก) ในบทความนี้เราพูดถึงทั้งสองด้าน โดยใช้เฉพาะตัวอย่างที่ตรวจสอบแล้วว่ามีอยู่จริง

## skill-creator: skill ที่เขียน skill

skill-creator ในที่เก็บทางการ anthropics/skills ของ Anthropic ออกแบบมาเพื่อสร้าง skill ใหม่ แก้ไขและปรับปรุง skill ที่มีอยู่ และวัดประสิทธิภาพของมัน ตามคำอธิบาย มันยังรับหน้าที่รันการประเมิน (eval) เปรียบเทียบผลด้วยการวิเคราะห์ความแปรปรวน และปรับคำอธิบายของ skill ให้ถูกเรียกใช้ได้ดีขึ้น

ขั้นตอนทำงานถูกอธิบายอย่างเป็นธรรมชาติมาก: ตัดสินใจว่าต้องการอะไร เขียนร่าง เตรียมข้อความทดสอบสองสามข้อความ รัน Claude ที่มี skill ด้วยข้อความเหล่านั้น ประเมินผลร่วมกัน เขียนใหม่ แล้ววนซ้ำ ในโฟลเดอร์มีสคริปต์แยกสำหรับรันการประเมิน สร้างรายงานเปรียบเทียบ และปรับปรุงคำอธิบาย รวมถึง "eval-viewer" สำหรับดูผลเป็นภาพ

คู่มือการปรับคำอธิบายของ agentskills.io ก็ยกให้ skill นี้เป็นตัวอย่าง ตามคู่มือ skill-creator ทำวงจรนี้เป็นอัตโนมัติตั้งแต่ต้นจนจบ: แบ่งชุดทดสอบ วัดอัตราการถูกเรียกใช้แบบขนาน ให้ Claude เสนอการปรับปรุงคำอธิบาย และสร้างรายงาน HTML สด

> **รู้หรือไม่?** ในการทดสอบการถูกเรียกใช้ที่ agentskills.io แนะนำ ใช้ข้อความตัวอย่างราว 20 ข้อความ และรันแต่ละข้อความ 3 ครั้ง นั่นคือการลองคำอธิบายเพียงชุดเดียวเท่ากับ 60 รอบ เพื่อป้องกันการเรียนรู้เกินพอดี (overfitting) ข้อความราว 60 เปอร์เซ็นต์ใช้สำหรับปรับปรุง และอีก 40 เปอร์เซ็นต์กันไว้ใช้ตรวจสอบเท่านั้น คู่มือบอกว่าส่วนใหญ่ห้ารอบก็เพียงพอ

## mcp-builder และ claude-api: สำหรับคนสร้างการเชื่อมต่อ

- **mcp-builder (ทางการ):** คู่มือสำหรับพัฒนาเซิร์ฟเวอร์ MCP ที่ทำให้โมเดลภาษาขนาดใหญ่สื่อสารกับบริการภายนอกผ่านเครื่องมือที่ออกแบบมาอย่างดี ทำงานได้กับ Python (FastMCP) หรือ Node/TypeScript (MCP SDK) skill แบ่งกระบวนการเป็นสี่ขั้น: วิจัยและวางแผน ลงมือทำ ทบทวนและทดสอบ และสร้างการประเมิน ในโฟลเดอร์มีเอกสารอ้างอิงแยกตามภาษาและสคริปต์ประเมินผล
- **claude-api (ทางการ):** skill อ้างอิงสำหรับ Claude API และ SDK ของ Anthropic ครอบคลุมเรื่องรหัสโมเดล พารามิเตอร์ การสตรีม การใช้เครื่องมือ และการแคช และมีโฟลเดอร์แยกสำหรับภาษาโปรแกรมหลายภาษา ตามเอกสารของ Claude skill โอเพนซอร์สตัวนี้มากับ Claude Code
- **webapp-testing (ทางการ):** ชุดเครื่องมือสำหรับทดสอบเว็บแอปในเครื่องด้วย Playwright เป็นตัวช่วยที่ใช้งานได้จริงสำหรับคนทำส่วนหน้าบ้าน ซึ่งเรากล่าวถึงในบทความเรื่องการออกแบบด้วย

## จากชุมชน: วินัยทางวิศวกรรมกับ Superpowers

นอกจากที่เก็บทางการแล้ว หนึ่งในชุดที่นักพัฒนาพูดถึงมากที่สุดคือที่เก็บ obra/superpowers ของ Jesse Vincent ซึ่งใช้ใบอนุญาต MIT ที่เก็บนี้นิยามตัวเองว่าเป็น "ระเบียบวิธีพัฒนาซอฟต์แวร์ที่สมบูรณ์" สำหรับเอเจนต์เขียนโค้ด ณ เดือนตุลาคม 2026 ในที่เก็บมี skill ดังนี้ (คัดบางส่วน):

| Skill | เริ่มทำงานเมื่อไร |
|---|---|
| brainstorming | ก่อนเริ่มฟีเจอร์ใหม่หรืองานสร้างสรรค์ |
| writing-plans | เมื่อเขียนแผนสำหรับงานหลายขั้นตอนก่อนแตะโค้ด |
| test-driven-development | ระหว่างลงมือทำ: เขียนเทสต์ที่ล้มเหลวก่อน แล้วค่อยเขียนโค้ดให้น้อยที่สุด |
| systematic-debugging | เมื่อเจอบั๊กหรือเทสต์ที่ล้มเหลว ก่อนเสนอวิธีแก้ |
| verification-before-completion | เพื่อรันคำสั่งตรวจสอบก่อนจะบอกว่า "เสร็จแล้ว" |

README ของที่เก็บมีคำแนะนำการติดตั้งสำหรับเอเจนต์หลายตัว ทั้ง Codex, Cursor, Gemini CLI และ GitHub Copilot CLI นอกเหนือจาก Claude Code และระบุว่าฝั่ง Claude Code อยู่ในตลาดปลั๊กอินทางการของ Anthropic นี่คือผลในทางปฏิบัติของการที่ Agent Skills เป็นมาตรฐานเปิด: skill ตัวเดียวกันใช้ได้กับเครื่องมือต่างกัน

## แนวคิดเดียวกันบนแพลตฟอร์มอื่น

เอกสาร ChatGPT และ Codex ของ OpenAI ก็นิยาม skill ว่าสร้างบน "มาตรฐาน agent skills แบบเปิด" ณ เดือนตุลาคม 2026 ในเอกสารมีตัวช่วยในตัวสองตัวที่เด่น: skill-creator ที่สร้าง skill จากงานที่คุณอธิบาย (เรียกใน Codex ด้วย $skill-creator) และ skill-installer ที่ติดตั้ง skill สำเร็จรูปจากที่เก็บ openai/skills หรือที่เก็บอื่น Codex อ่าน skill ในเครื่องจากโฟลเดอร์ .agents/skills ทั้งระดับโปรเจกต์และระดับผู้ใช้

สำหรับนักพัฒนา นิสัยที่มีค่าที่สุดอาจเป็นดังนี้: เปลี่ยนคำอธิบายยาว ๆ ทุกอย่างที่คุณพูดซ้ำ รายการตรวจสอบโค้ดรีวิว หรือขั้นตอนการดีพลอย ให้เป็น skill แล้ววางไว้ในที่เก็บของโปรเจกต์ ใน Claude Code skill ที่วางในโฟลเดอร์ .claude/skills จะไปถึงทีมพร้อมกับที่เก็บด้วย แต่อย่าลืมอ่านสคริปต์ของ skill จากชุมชนทุกตัวที่คุณติดตั้ง เพราะ skill เหล่านี้รันโค้ดบนเครื่องของคุณด้วยสิทธิ์ของคุณได้

ในกระบวนการพัฒนาของคุณ ขั้นตอนไหนที่ทำให้คิดว่า "ถ้ามี skill ก็ดี": การทดสอบ การรีวิวโค้ด หรือการดีพลอย?
