การเขียน skill ไม่จำเป็นต้องเป็นโปรแกรมเมอร์ ในรูปแบบที่ง่ายที่สุด แค่โฟลเดอร์หนึ่งใบกับไฟล์ข้อความหนึ่งไฟล์ก็พอ แต่ความต่างระหว่าง skill ที่ทำงานได้ดีกับ skill ที่ไม่เคยถูกเรียกใช้เลย มักซ่อนอยู่ในประโยคเดียว คือคำอธิบาย ในบทความนี้เราจะเขียน skill เล็ก ๆ แต่ใช้งานได้จริงตั้งแต่ศูนย์

## ขั้นที่ 1: สร้างโฟลเดอร์และ SKILL.md

ตามข้อกำหนดของ Agent Skills skill คือโฟลเดอร์ที่มีไฟล์ SKILL.md อย่างน้อยหนึ่งไฟล์ ส่วนบนสุดของไฟล์เป็นข้อมูลนำ YAML (frontmatter) และมีสองช่องที่บังคับ:

- **name:** ยาวไม่เกิน 64 อักขระ ใช้ได้เฉพาะตัวพิมพ์เล็ก ตัวเลข และขีดกลาง ห้ามขึ้นต้นหรือลงท้ายด้วยขีดกลาง ห้ามมีขีดกลางสองตัวติดกัน และต้องตรงกับชื่อโฟลเดอร์ เอกสารของ Claude ยังระบุว่าห้ามใช้คำว่า "anthropic" และ "claude" ในชื่อ
- **description:** ห้ามว่าง ยาวไม่เกิน 1,024 อักขระ ต้องบอกว่า skill ทำอะไรและควรใช้เมื่อไร

ยังมีช่องที่ไม่บังคับอีก (license, compatibility, metadata และ allowed-tools แบบทดลอง) แต่ skill ส่วนใหญ่ไม่ต้องใช้

## ขั้นที่ 2: เขียนคำอธิบายให้พิถีพิถัน

ทำไมคำอธิบายสำคัญขนาดนี้ เพราะตอนเริ่มต้น เอเจนต์อ่านเฉพาะชื่อและคำอธิบายของแต่ละ skill ตามถ้อยคำของ agentskills.io "ภาระทั้งหมด" ของการถูกเรียกใช้อยู่บนบ่าของคำอธิบาย ถ้าคำอธิบายไม่บอกว่างานไหนจะใช้ skill นี้ เอเจนต์ก็ไม่เอื้อมไปหยิบมัน

ข้อแนะนำจากแหล่งอ้างอิงสรุปได้ดังนี้:

- เขียนทั้ง **สิ่งที่ทำ** และ **เวลาที่ควรใช้**
- เอกสารของ Claude แนะนำให้เขียนเป็น **บุรุษที่สาม** เพราะคำอธิบายถูกใส่ในพรอมต์ระบบ (เช่น "ประมวลผลไฟล์ Excel" ไม่ใช่ "ฉันช่วยคุณได้")
- agentskills.io แนะนำให้ระบุกรณีที่ผู้ใช้ไม่ได้เอ่ยถึงงานนั้นตรง ๆ ไว้ด้วย
- เขียนให้สั้น: ไม่กี่ประโยค อย่างมากหนึ่งย่อหน้าสั้น ๆ Claude Code ตัดคำอธิบายในรายการที่ 1,536 อักขระ ดังนั้นกรณีใช้งานที่สำคัญที่สุดต้องอยู่ต้น ๆ

## ขั้นที่ 3: เนื้อหาให้สั้น สคริปต์ให้ฉลาด

ลองนึกถึง skill ตามกฎการเขียนของบล็อกนี้เอง คือในข้อความห้ามเหลือขีดยาว (em dash) และขีดกลางความยาวปานกลาง (en dash) โครงสร้างโฟลเดอร์เป็นดังนี้:

```
tire-denetimi/
├── SKILL.md
└── scripts/
    └── tire_bul.py
```

และไฟล์ SKILL.md มีเพียงเท่านี้:

```markdown
---
name: tire-denetimi
description: Türkçe blog yazılarında uzun tire (U+2014) ve orta tire (U+2013) kullanımını bulur ve düzeltme önerir. Kullanıcı bir Markdown yazısını yayına hazırlarken, "tireleri kontrol et", "yazım kurallarına uyuyor mu" dediğinde ya da adını anmasa da yayın öncesi son kontrol istediğinde kullanılır.
---

# Tire denetimi

1. `python scripts/tire_bul.py <dosya.md>` komutunu çalıştır.
2. Çıktıdaki her satır için tireyi nokta, virgül, iki nokta veya parantezle değiştirmeyi öner.
3. Anlamı değiştirme. Emin olmadığın satırları kullanıcıya sor.
4. Sonunda kaç satır düzelttiğini tek cümleyle bildir.
```

เอกสารของ Claude มองหน้าต่างบริบทเป็น "ทรัพยากรส่วนกลาง" และแนะนำให้ใส่เฉพาะข้อมูลที่โมเดลยังไม่รู้อยู่แล้ว เนื้อหาหลักควรสั้นกว่า 500 บรรทัด เอกสารอ้างอิงยาว ๆ ควรย้ายไปไฟล์แยก และลิงก์จาก SKILL.md ไปยังไฟล์เหล่านั้นแค่ชั้นเดียว

กฎสำหรับสคริปต์ก็ชัดเจน: "แก้ให้จบ อย่าโยนภาระ" คือสคริปต์ควรจัดการกรณีข้อผิดพลาดเอง ไม่ใช่เขียนแบบ "ปล่อยให้พัง เดี๋ยว Claude หาทางเอง" เมื่อสคริปต์ทำงาน สิ่งที่เข้าสู่บริบทคือผลลัพธ์ ไม่ใช่ตัวโค้ด ทำให้สคริปต์เชื่อถือได้มากกว่าคำสั่งสำหรับงานที่ซ้ำและไม่ยอมให้ผิดพลาด

> **รู้หรือไม่?** ใน Claude Code "คำสั่งสแลชแบบกำหนดเอง" รุ่นเก่ารวมเข้ากับ skill แล้ว ไฟล์ .claude/commands/deploy.md และ .claude/skills/deploy/SKILL.md สร้างคำสั่ง /deploy เดียวกัน ถ้าไม่ต้องการให้ skill ถูกเรียกอัตโนมัติ ให้เพิ่ม disable-model-invocation: true ใน frontmatter แล้วเรียกใช้ด้วยมือเท่านั้น

## ขั้นที่ 4: ทดสอบ แล้วทดสอบอีก

คู่มือแนวปฏิบัติที่ดีที่สุดของ Claude แนะนำให้เตรียมสถานการณ์ประเมินผลก่อนเขียนเอกสารยาว ๆ และในรายการตรวจสอบก่อนเผยแพร่มีการประเมินอย่างน้อยสามชุด และทดสอบแยกกับโมเดล Haiku, Sonnet และ Opus เหตุผลง่าย ๆ: คำสั่งที่ทำงานสมบูรณ์แบบบน Opus อาจต้องการรายละเอียดมากกว่านี้สำหรับ Haiku

สำหรับทดสอบการถูกเรียกใช้ ข้อเสนอของ agentskills.io เป็นรูปธรรม: เตรียมข้อความผู้ใช้ตัวอย่างประมาณ 20 ข้อความ ให้ 8 ถึง 10 ข้อความเรียก skill และอีก 8 ถึง 10 ข้อความไม่เรียก ตัวอย่างเชิงลบที่มีค่าที่สุดคือ "เฉียดฉิว" คือข้อความที่ใช้คำเดียวกันแต่ขอให้ทำงานอย่างอื่น เพราะพฤติกรรมของโมเดลไม่เหมือนกันทุกครั้ง จึงแนะนำให้รันแต่ละข้อความหลายครั้ง (เริ่มต้นที่ 3 ครั้ง) แล้วดูอัตราการถูกเรียกใช้

| คำอธิบายที่ไม่ดี | คำอธิบายที่ดี |
|---|---|
| "ช่วยเรื่อง PDF" | บอกว่าทำอะไรและใช้เมื่อไร |
| มีแต่รายละเอียดทางเทคนิค | อธิบายเจตนาของผู้ใช้ |
| ครอบคลุมทุกอย่าง | ระบุด้วยว่าไม่ทำอะไร |

การติดตั้งก็ง่าย: ใน Claude Code แค่วางโฟลเดอร์ไว้ใต้ ~/.claude/skills/ (ส่วนตัว) หรือในโฟลเดอร์ .claude/skills/ ของโปรเจกต์ Claude Code เฝ้าดูโฟลเดอร์เหล่านี้และรับรู้การเปลี่ยนแปลงในเซสชันเดิมโดยไม่ต้องรีสตาร์ต ส่วนใน claude.ai คุณอัปโหลด skill เป็นไฟล์ zip ได้จากหน้าการตั้งค่า

skill แรกของคุณจะทำให้งานซ้ำ ๆ อะไรเป็นอัตโนมัติ?
