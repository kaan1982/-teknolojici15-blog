ผู้ช่วย AI รู้ทุกเรื่องนิดหน่อย แต่ไม่รู้เทมเพลตรายงานของบริษัทคุณ สีประจำแบรนด์ หรือเคล็ดลับการจัดการไฟล์บางประเภทให้ถูกต้อง ถ้าแทนที่จะอธิบายยาว ๆ ทุกครั้งที่คุยกัน คุณแพ็กความรู้เหล่านั้นไว้ครั้งเดียวแล้วบอกเอเจนต์ว่า "ใช้เมื่อจำเป็น" ได้ล่ะ นั่นคือแนวคิดของ "skill" (ทักษะ)

## สั้น ๆ: โฟลเดอร์หนึ่งกับไฟล์ SKILL.md

ตามคำนิยามของ Anthropic Agent Skills คือแพ็กเกจแบบโมดูลที่ขยายความสามารถของ Claude แต่ละ skill รวมคำสั่ง เมทาดาทา และทรัพยากรเสริม (สคริปต์ เทมเพลต) ไว้ด้วยกัน และ Claude จะใช้มันเองเมื่อเกี่ยวข้อง บล็อกวิศวกรรมของ Anthropic พูดให้เรียบง่ายกว่านั้นอีก: skill คือ "โฟลเดอร์ของคำสั่ง สคริปต์ และทรัพยากรที่จัดระเบียบแล้ว" ซึ่งเอเจนต์โหลดเข้ามาในจังหวะที่ต้องการเพื่อทำงานเฉพาะอย่างให้ดีขึ้น

ในทางเทคนิค skill คือโฟลเดอร์ที่อย่างน้อยต้องมีไฟล์ชื่อ SKILL.md ส่วนหัวของไฟล์เป็น YAML ที่มีสองช่องบังคับ คือ name (ชื่อ) และ description (คำอธิบาย) ถัดลงมาเป็นคำสั่งที่เขียนด้วย Markdown ธรรมดา และคุณจะเพิ่มโฟลเดอร์ย่อยอย่าง scripts/ (โค้ดที่รันได้) references/ (เอกสารเพิ่มเติม) และ assets/ (เทมเพลต รูปภาพ ข้อมูล) ได้ตามต้องการ

Anthropic เปรียบโครงสร้างนี้กับคู่มือปฐมนิเทศที่เตรียมไว้ให้พนักงานใหม่ คุณวางคู่มือไว้บนโต๊ะ แล้วพนักงานจะเปิดดูเมื่อต้องใช้

## เคล็ดลับ: ไม่ได้โหลดทุกอย่างพร้อมกัน

สิ่งที่ทำให้ skill ต่างจาก prompt ยาว ๆ ทั่วไปคือดีไซน์ที่เรียกว่า "การเปิดเผยทีละขั้น" (progressive disclosure) ตามเอกสารของ Claude เนื้อหาถูกโหลดเป็นสามชั้น:

| ชั้น | โหลดเมื่อไร |
|---|---|
| 1. เมทาดาทา (ชื่อ + คำอธิบาย) | ทุกครั้งตอนเริ่มต้น (ประมาณ 100 โทเค็นต่อ skill) |
| 2. เนื้อหาหลักของ SKILL.md | เมื่อ skill ถูกเรียกใช้ (แนะนำให้ไม่เกิน 5,000 โทเค็น) |
| 3. ไฟล์เพิ่มเติมและสคริปต์ | เฉพาะเมื่อจำเป็น และมีเฉพาะผลลัพธ์ของสคริปต์เท่านั้นที่เข้าสู่บริบท |

ด้วยวิธีนี้ คุณติดตั้ง skill ให้เอเจนต์ได้หลายสิบตัวโดยที่ทั้งหมดไม่เบียดหน้าต่างบริบทจนเต็ม จนกว่าจะถูกเรียกใช้ แต่ละ skill จะ "อยู่บนโต๊ะ" แค่ชื่อกับคำอธิบาย ในตัวอย่างจากเอกสาร skill สำหรับ PDF เก็บคำสั่งการกรอกฟอร์มไว้ในไฟล์ forms.md แยกต่างหาก และ Claude จะอ่านไฟล์นั้นก็ต่อเมื่อต้องกรอกฟอร์มจริง ๆ เท่านั้น

> **รู้หรือไม่?** Anthropic ประกาศ Agent Skills เมื่อวันที่ 16 ตุลาคม 2025 และเมื่อวันที่ 18 ธันวาคม 2025 ได้เผยแพร่รูปแบบนี้เป็นมาตรฐานเปิดที่ agentskills.io ด้วยเหตุนี้ ณ เดือนตุลาคม 2026 คุณจึงเห็นโครงสร้าง SKILL.md แบบเดียวกันในเอกสารของเครื่องมืออื่นอย่าง GitHub Copilot และ OpenAI Codex เอกสารของ Copilot ยังชี้ให้ไปดูข้อกำหนดของ agentskills.io โดยตรงเพื่อตรวจสอบ skill

## Prompt, MCP, ปลั๊กอิน: ต่างกันอย่างไร?

แนวคิดเหล่านี้มักถูกสับสน เพราะทั้งหมดเกี่ยวกับ "ทำให้เอเจนต์เก่งขึ้น" การแบ่งของศูนย์ช่วยเหลือ Claude สรุปได้ดังนี้:

- **Prompt หรือคำสั่งแบบกำหนดเอง:** แนวทางทั่วไปที่ใช้ในแต่ละแชตหรือทุกแชต ส่วน skill เฉพาะเจาะจงกับงาน และทำงานเฉพาะเมื่อเกี่ยวข้อง
- **โปรเจกต์:** ความรู้พื้นหลังคงที่ที่โหลดอยู่ตลอดในแชตภายในโปรเจกต์ ส่วน skill เป็นขั้นตอนที่เปิดขึ้นมาเมื่อต้องใช้
- **ตัวเชื่อม MCP (Model Context Protocol):** เชื่อม Claude เข้ากับบริการและแหล่งข้อมูลภายนอก คือให้ "การเข้าถึง" ส่วน skill คือ "ความรู้เชิงวิธีการ" ว่าจะใช้การเข้าถึงนั้นอย่างไร ศูนย์ช่วยเหลือระบุว่าสองอย่างนี้มักใช้ร่วมกัน
- **ปลั๊กอิน (plugin):** ใน Claude Code และ Cowork ปลั๊กอินคือแพ็กเกจสำหรับแจกจ่ายหลายส่วนไปด้วยกัน (skill ตัวเชื่อม คำสั่ง เอเจนต์ย่อย) เอกสารของ OpenAI แยกในทำนองเดียวกัน: skill คือรูปแบบการเขียน ส่วนปลั๊กอินคือรูปแบบการแจกจ่าย

สรุปคือ MCP ให้มือแก่เอเจนต์ skill สอนมือนั้นให้มีฝีมือ และปลั๊กอินส่งมอบทั้งหมดมาในกล่องเดียว

## ใช้งานได้ที่ไหน?

ณ เดือนตุลาคม 2026 ตามเอกสารของ Claude สามารถใช้ skill ได้ในแอป Claude (claude.ai) ใน Claude Code และใน Claude API ร่วมกับเครื่องมือรันโค้ด ศูนย์ช่วยเหลือระบุว่า skill มีให้ในแพลน Free, Pro, Max, Team และ Enterprise และต้องเปิดใช้ฟีเจอร์รันโค้ดไว้

รายละเอียดสำคัญข้อหนึ่ง: skill ที่คุณสร้างเองไม่ซิงก์ข้ามแพลตฟอร์ม skill ที่อัปโหลดเข้า claude.ai ใช้ได้เฉพาะบัญชีของคุณ skill ที่อัปโหลดเข้า API แชร์กับทั้งเวิร์กสเปซ ส่วนใน Claude Code จะเก็บไว้เป็นของส่วนตัว (~/.claude/skills/) หรือในโฟลเดอร์โปรเจกต์ (.claude/skills/)

และยังมีมิติด้านความปลอดภัยด้วย เพราะ skill รันโค้ดได้ เอกสารจึงแนะนำให้ปฏิบัติต่อมัน "เหมือนการติดตั้งซอฟต์แวร์" และใช้จากแหล่งที่เชื่อถือได้เท่านั้น เราพูดถึงเรื่องนี้แยกต่างหากในบทความสุดท้ายของชุดนี้

ในบทความถัดไปของส่วนนี้ เราจะเขียน skill ของคุณเองทีละขั้น และสำรวจ skill ที่มีอยู่จริงและใช้ได้ผลทีละหมวด

งานอะไรที่คุณต้องอธิบายให้ AI ฟังซ้ำแล้วซ้ำอีกทุกวัน และคิดว่า "ถ้าสอนครั้งเดียวได้ก็ดี"?
