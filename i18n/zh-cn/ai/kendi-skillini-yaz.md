写一个 skill 不需要你是程序员。最简单的情况下，一个文件夹和里面一个文本文件就够了。但一个运转良好的 skill 和一个从不被触发的 skill 之间的区别，往往藏在一句话里：描述。这篇文章里，我们从零开始写一个小而真实的 skill。

## 第 1 步：创建文件夹和 SKILL.md

按 Agent Skills 规范，一个 skill 是至少包含一个 SKILL.md 文件的文件夹。文件最开头是 YAML 前置信息（frontmatter），有两个必填字段：

- **name：** 最多 64 个字符。只能用小写字母、数字和连字符。不能以连字符开头或结尾，不能包含连续两个连字符，且必须与文件夹同名。Claude 的文档还指出，名称里不能使用“anthropic”和“claude”这两个词。
- **description：** 不能为空，最多 1,024 个字符。应该说明 skill 做什么、什么时候使用。

还有可选字段（license、compatibility、metadata 和实验性的 allowed-tools），但大多数 skill 用不着。

## 第 2 步：精心写好描述

描述为什么这么重要？因为智能体在启动时只读取每个 skill 的名称和描述。用 agentskills.io 的话说，触发的“全部重担”都压在描述身上。如果描述没有说明这项工作什么时候有用，智能体就不会去用那个 skill。

资料的建议可以概括如下：

- 既写**它做什么**，也写**什么时候使用**。
- Claude 的文档建议用**第三人称**来写，因为描述会被加入系统提示（例如“处理 Excel 文件”，而不是“我可以帮你”）。
- agentskills.io 建议，把用户没有点名那个领域的情形也明确列出来。
- 保持简短：几句话，最多一小段。Claude Code 在列表里会把描述截断在 1,536 个字符，所以最重要的使用场景要放在前面。

## 第 3 步：正文要短，脚本要聪明

举个例子，设想一个符合本博客写作规范的 skill：文本里不能留下长破折号（em dash）和短破折号（en dash）。文件夹结构如下：

```
tire-denetimi/
├── SKILL.md
└── scripts/
    └── tire_bul.py
```

SKILL.md 文件只有这么多：

```markdown
---
name: tire-denetimi
description: 查找中文博客文章中长破折号（U+2014）和短破折号（U+2013）的使用并给出修改建议。当用户准备发布 Markdown 文章，说“检查破折号”“是否符合写作规范”，或者没有点名但想在发布前做最后检查时使用。
---

# 破折号检查

1. 运行 `python scripts/tire_bul.py <文件.md>` 命令。
2. 对输出中的每一行，建议用句号、逗号、冒号或括号替换破折号。
3. 不要改变原意。对没有把握的行，询问用户。
4. 最后用一句话告知修改了多少行。
```

Claude 的文档把上下文窗口看作“公共资源”，建议只加入模型本来不知道的信息。正文应保持在 500 行以内。长的参考文本应移到单独的文件里，并从 SKILL.md 以一层的深度链接到这些文件。

脚本的规则也很明确：“解决问题，不要甩锅”。也就是说，脚本应该自己处理出错的情况，不能抱着“崩了就崩了，Claude 会想办法”的心态来写。脚本运行时，进入上下文的不是代码本身，而只是它的输出。这使得脚本在重复性、容不得出错的工作上，比指令更可靠。

> **你知道吗？** 在 Claude Code 中，旧的“自定义斜杠命令”已经与 skill 合并。.claude/commands/deploy.md 文件和 .claude/skills/deploy/SKILL.md 创建的是同一个 /deploy 命令。如果你不希望某个 skill 被自动触发，可以在 frontmatter 里加上 disable-model-invocation: true，只允许手动调用。

## 第 4 步：测试，再测试

Claude 的最佳实践指南建议，在写长文档之前先准备评估场景，发布前的检查清单里包括至少三个评估，以及分别在 Haiku、Sonnet 和 Opus 模型上测试。理由很简单：在 Opus 上完美运行的指令，在 Haiku 上可能需要更多细节。

要测试触发情况，agentskills.io 的建议很具体：准备大约 20 条示例用户消息。其中 8 到 10 条应该触发 skill，8 到 10 条不该触发。最有价值的反例是“险些擦边”的，也就是用词相同、但要求做另一件事的消息。由于模型的行为并不每次都一样，建议把每条消息运行几次（起步先 3 次），看触发率。

| 糟糕的描述 | 好的描述 |
|---|---|
| “帮助处理 PDF。” | 说明它做什么、什么时候使用 |
| 只有技术细节 | 描述用户的意图 |
| 什么都涵盖 | 也说明它不做什么 |

安装也很简单：在 Claude Code 中，把文件夹放进 ~/.claude/skills/（个人）或项目的 .claude/skills/ 文件夹即可。Claude Code 会监视这些文件夹，并在同一个会话中感知变化，无需重启。在 claude.ai 里，你可以在设置中把 skill 作为 zip 上传。
