让 skill 如此强大的东西，也让它有风险：一个 skill 不只是文本，还可能携带可执行的代码。智能体加载某个 skill 后，会把其中的指令当作自己的指令来遵循，并且可以运行其中的脚本。因此 Claude 文档的建议可以用一句话概括：把安装 skill 当作安装软件。

## 官方资料怎么说？

Claude 文档中的安全部分相当直接。它建议你只使用来自可信来源的 skill，也就是你自己写的，或来自 Anthropic 的。如果你不得不使用来源不明的 skill，它要求你“格外小心”，并在使用前从头到尾审查。

Anthropic 的工程文章也是同一思路：对于来自不太可信来源的 skill，建议检查打包的文件，尤其是代码依赖和脚本，还要检查那些让它连接外部网络的指令。文档还特别强调了一个风险：从外部地址拉取数据的 skill 很危险，因为拉取到的内容可能带有恶意指令。

## 现实中发生了什么？

这些警告并非纸上谈兵。安全公司 Snyk 在 2026 年 2 月 5 日发布的“ToxicSkills”研究中，扫描了来自 ClawHub 和 skills.sh 的 3,984 个 skill。结果如下：

| 发现 | 数量 |
|---|---|
| 被扫描的 skill | 3,984 |
| 至少有一个安全问题的 | 1,467（36.82%） |
| 至少含一个严重问题的 | 534（13.4%） |
| 已确认的恶意载荷 | 76 |

据报告，skills.sh 的数据只涵盖该网站精选的前 100 个 skill，完整的市场数字则是针对 ClawHub 的。可以看到的攻击类型包括：诱导用户下载并运行不可信软件的安装指令、把凭据发送给攻击者的隐藏（用 Base64 或 Unicode 伪装的）命令，以及关闭安全检查和安装后门的企图。在已确认的恶意 skill 中，91% 使用了提示注入（prompt injection）。

> **你知道吗？** 据 Claude 帮助中心，Enterprise 组织可以开启 skill 扫描，检查上传的 skill 和插件中是否有恶意内容。但这只是一张安全网，替代不了阅读。要了解一个 skill 做了什么，最好的办法是在安装之前，自己打开读一读它的 SKILL.md 和脚本。

## 安装之前的检查清单

这是我们根据文档建议和现场发现整理的实用清单：

1. **核实来源。** 仓库是谁的？是正式公司或知名开发者，还是一个与著名包名极为相似的仿冒品（typosquatting）？
2. **把 SKILL.md 从头读到尾。** 像“先下载并运行这个”“关闭安全设置”“发送到这个地址”之类的说法，都是警报信号。
3. **检查 scripts/ 文件夹。** 如果有你看不懂、被混淆或用 Base64 编码的行，就不要安装。
4. **检查外部链接。** 如果 skill 从某个网址拉取指令或数据，别忘了那里的内容随时可能改变。
5. **只装你需要的。** 与其“全都装上”，不如逐个挑选，这既缩小上下文，也缩小攻击面。

## 最小权限与密钥

skill 在哪里运行也很重要。按 Claude 的文档，在 Claude API 环境中，skill 没有网络访问，运行时也不能安装软件包。在 claude.ai 中，网络访问可能依据用户和管理员的设置为完全、部分或关闭。而在 Claude Code 中，skill 拥有和你电脑上任何程序一样的网络访问。也就是说，你在本地智能体上安装的 skill，是以你的权限运行的。

所以最小权限原则至关重要。在 Claude Code 中，skill 的 frontmatter 里的 allowed-tools 字段，可以让某些工具在该 skill 被调用时无需询问就能使用。按文档，这项许可在你的下一条消息时就会重置。即便如此，如果你在别人写的 skill 里看到宽泛的权限，不经有意识的确认就不安装，是个好习惯。

对于密钥，规则很简单：永远不要把 API 密钥、密码和访问令牌写进 SKILL.md 或 skill 文件夹。你分享 skill 或把它推送到仓库时，那个文件夹里的一切也会跟着出去。把密钥放在环境变量或你所用工具的安全凭据存储里，在 skill 里只说明如何访问它们。

截至 2026 年 10 月，skill 生态正在飞速增长，这种增长让人想起应用商店最初几年的安全问题。好消息是：读一个 skill 比读一个应用的源代码容易得多，因为它大部分是纯文本。

安装 skill 之前，你会打开读一读里面的内容，还是只相信星标数和下载量？
